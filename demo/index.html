Documentation your readers can run.

docsterm drops a live console into any docs page. Commands execute in the reader browser - no servers, no VMs. The AI layer turns a plain-language request into the right command, and explains the error when something breaks.

install npm i docsterm @xterm/xterm
01

Why a terminal in the docs

01

Copy-paste loses readers

A reader leaves the page for their own shell, mistypes a flag, and never comes back to step four. Every context switch is a drop-off you never see.

02

Hosted sandboxes are heavy

Killercoda, Instruqt and friends boot server VMs: thousands a month, an ops burden, and a separate platform your docs have to link away to.

03

The page is the context

docsterm runs client-side and reads the page it sits on - title, description, headings. The assistant already knows which tutorial the reader is in.

02

Code blocks that run

Mark a code block and docsterm adds a run button to it. Lines that start with $ are the commands; everything else is shown output.

  1. Create the project

    Writes orbit.toml into the current folder.

    $ orbit init
Created orbit.toml
Project initialized.

  2. Ship it

    Uploads the bundle and prints the address.

    $ orbit deploy
Uploading bundle... done
Deployed to https://demo.orbit.app

  3. Check on it

    Shows the state of the deployment.

    $ orbit status
status: RUNNING
region: eu-central
version: 14

Any framework: one HTML tag

Vue, Svelte, Astro, VitePress or a plain HTML page: call defineDocsTerminal() once and write the tag. 

<script type="module">
  import { defineDocsTerminal } from 'docsterm/element'
  defineDocsTerminal()
</script>

<docs-terminal backend="javascript"></docs-terminal>
08

Five minutes to embed

One React component, or a few lines of vanilla JS. Recipes for Docusaurus, Next.js, Vite and plain HTML are in the embedding guide.

React (Docusaurus, Next, Vite)

import '@xterm/xterm/css/xterm.css'
import { useState } from 'react'
import { DocsTerminal } from 'docsterm/react'
import {
  createPyodideBackend,
} from 'docsterm/pyodide'

export function Playground() {
  const [backend] = useState(
    () => createPyodideBackend(),
  )
  return <DocsTerminal backend={backend} />
}

Vanilla

import '@xterm/xterm/css/xterm.css'
import {
  DocsTerminal,
  attachRunButtons,
} from 'docsterm'
import { createShellBackend } from 'docsterm/shell'

const terminal = new DocsTerminal({
  backend: createShellBackend(),
})
await terminal.mount(
  document.querySelector('#terminal'),
)
attachRunButtons(document, terminal)
