### `docsterm/shell`

Оболочка над виртуальной файловой системой, ваш собственный CLI в роли команды. Работает прямо на странице и не требует сети.

```ts
import { createShellBackend, type ShellCommand } from 'docsterm/shell'

const orbit: ShellCommand = async (ctx) => {
  if (ctx.argv[1] !== 'deploy') {
    return { stderr: `orbit: unknown command '${ctx.argv[1] ?? ''}'\n`, exitCode: 2 }
  }
  ctx.write?.('uploading build...\n')
  await new Promise((resolve) => setTimeout(resolve, 500))
  if (ctx.signal?.aborted) return { exitCode: 130 }
  return 'Deployed to https://demo.orbit.app\n'
}

export const backend = createShellBackend({
  cwd: '/project',
  env: { PROJECT: 'orbit' },
  files: {
    project: {
      'README.md': '# demo app\n',
      'regions.csv': 'name,region\nalpha,eu\nbeta,us\n',
      src: { 'index.ts': 'export const answer = 42\n' },
    },
  },
  commands: { orbit },
})
```

Читатель может выполнить `ls`, `cd src`, `grep eu regions.csv | wc -l`, `echo "Deploying $PROJECT" > notes.txt && cat notes.txt`, `find / -name "*.ts"` или `orbit deploy` — с настоящими кодами возврата, которые потом разбирает `explain`.

Опции:

| Опция | По умолчанию | Значение |
| --- | --- | --- |
| `files` | `{}` | Дерево файлов от `/`: строка — файл, объект — каталог |
| `cwd` | `/` | Начальный каталог; создаётся, если его нет |
| `env` | `HOME=/`, `SHELL=docsterm` | Переменные окружения (`PWD` следует за `cd`) |
| `commands` | `{}` | Ваши команды по имени; они важнее встроенных с тем же именем |
| `prompt` | `(cwd) => cwd + ' $ '` | Строка или `(cwd) => string` |
| `banner` | нет | Печатается один раз при старте |
| `colors` | `true` | `ls` раскрашивает каталоги, когда выводит в терминал |

Команда получает `ctx` с полями `argv` (`argv[0]` — имя), `stdin` (ввод из конвейера или перенаправления), `cwd`, `env`, `fs` (виртуальная файловая система), `setCwd()`, `write()`/`writeError()` (поток в терминал либо в конвейер или файл, куда пишет команда), `signal` (срабатывает по Ctrl+C), `isTTY`, `colors`, `columns`, `commands`, `lastStatus` и `locale`. Возвращает строку (stdout), `{ stdout, stderr, exitCode }`, [`InteractiveRun`](#интерактивные-программы) для полноэкранной программы или промис одного из них. Возвращённый текст печатается после всего, что команда вывела потоком. `undefined` считается успехом; `exitCode` приводится как статус процесса (`& 255`, дробная часть отбрасывается, `NaN` и `Infinity` дают 1); брошенная ошибка печатает `<имя>: <сообщение>` и даёт код 1.

**Синтаксис.** Эталон — POSIX `sh` в реализации `bash --posix` и поведение GNU coreutils в локали UTF-8:

- конвейеры `|` и `|&`, списки `&&`, `||`, `;` и переводы строк, отрицание `!`;
- перенаправления `>`, `>>`, `<`, `>|`, `2>`, `2>&1`, `>&2`, `&>`, `&>>`, `n>&-`, а также `/dev/null`, `/dev/stdout`, `/dev/stderr`; `>&file` отправляет stdout и stderr в `file`, как в bash;
- одинарные кавычки, двойные (с раскрытием `$` и экранированием `\`) и обратная косая черта;
- `$VAR`, `${VAR}`, `${VAR:-default}` и остальные формы `-`, `=`, `?`, `+` с `:` и без, `${#VAR}`, `${VAR#pattern}`, `##`, `%`, `%%`, `$?`, `$$`, `$#`, `$0`, `$(command)` и обратные кавычки;
- `~`, раскрытие фигурных скобок `{a,b}` и `{1..3}`, разбиение на поля результатов раскрытия без кавычек;
- шаблоны `*`, `?`, `[abc]`, `[!abc]` и классы POSIX вроде `[[:alpha:]]`; скрытые файлы подходят, только если шаблон начинается с `.`;
- присваивания `NAME=value` и `NAME=value command` для одной команды;
- комментарии `#`;
- `\` в конце, незакрытая кавычка или `|`, `&&`, `||` в конце строки продолжают команду на новой строке с приглашением `'> '`.

**Встроенные команды:** `basename cat cd clear cp dirname echo env export false find grep head help less ls mkdir more mv printf pwd rm sleep sort tail tee touch true type uniq unset wc which`. Неизвестная опция даёт код 2. `grep` понимает базовый синтаксис (`\|`), расширенный (`-E`), фиксированные строки (`-F`) и `-P` — регулярные выражения JavaScript. Tab дополняет команды в позиции команды и пути в остальных местах, понимает кавычки и `~`, экранирует пробелы и после `cd` предлагает только каталоги.

`less` и `more` — настоящие пейджеры на альтернативном экране: пробел/`f`/PgDn и `b`/PgUp листают страницы, `j`/вниз/Enter и `k`/вверх — строки, `d`/`u` сдвигают на полстраницы, `g`/Home и `G`/End прыгают в начало и конец, `q`, `Q`, `ZZ` или Ctrl+C выходят, `+G` открывает конец. Они читают конвейер (`cat log | less`), но их собственный вывод в конвейер не передать, а вне терминала (в файл, в `/dev/null`) они копируют текст, как `cat`.

**Ограничения.**

- Не поддерживаются подоболочки `( )`, группы команд `{ }`, функции, циклы, `if`/`case`, here-документы и here-строки, фоновые задачи `&`, `time`, арифметика `$(( ))`, подстановка процессов и `$'…'`. Такая строка печатает `docsterm: неподдерживаемый синтаксис: …`, даёт код 2 и не выполняется целиком.
- `IFS` фиксирован, позиционные параметры пусты.
- Сортировка (`ls`, шаблоны, `sort`) идёт по ICU-сравнению: знаки препинания и скрытые файлы раньше букв.
- `head -c`, `tail -c` и `printf '\xHH'` работают с символами, а не байтами.
- `ls missing` даёт код 1, как в BSD; GNU даёт 2.
- Раскрытие фигурных скобок останавливается на 10 000 слов и 256 уровнях вложенности.
- `grep -E` и `grep -P` выполняют регулярные выражения JavaScript в основном потоке страницы без ограничения времени: шаблон с катастрофическим перебором с возвратами подвешивает вкладку.
- Нет поиска `/` в пейджере, `grep -f`, запуска команды через `env` и строки `total` в `ls -l`.
- Оболочка работает в основном потоке страницы: своя команда, которая долго считает синхронно, блокирует страницу. Ctrl+C доходит до команд через `ctx.signal`.

### `docsterm/javascript`

REPL для JavaScript в Web Worker по образцу REPL Node.js.

```ts
import { createJavaScriptBackend } from 'docsterm/javascript'

const backend = createJavaScriptBackend({
  globals: { apiBase: 'https://api.example.com', users: ['ada', 'grace', 'linus'] },
  timeoutMs: 5000,
})
```

- Значение последнего выражения печатается в стиле Node (`Map(1) { 'a' => 1 }`, `[ 1, 2 ]`, строки в кавычках); возвращённый промис дожидается результата.
- Объявления `const`, `let`, `class` и `function` живут между командами, в том числе вместе с `await` верхнего уровня; повторный `const x = …` разрешён, как в DevTools.
- `console.log`, `info`, `warn`, `error`, `debug`, `table`, `dir`, `assert`, `count`, `countReset`, `time`, `timeEnd`, `group`, `groupEnd`, `trace` и спецификаторы `%s %d %i %f %o %O %c` печатают в терминал по ходу работы.
- Незаконченный код продолжается с приглашением `'... '` (разбор через acorn, он загружается при старте бэкенда).
- DOM нет. Относительные URL (`/`, `./`, `../`) считаются от страницы в `fetch`, `Request`, `XMLHttpRequest`, `importScripts` и `new URL()`; динамическому `import()` нужен абсолютный URL.
- Ctrl+C завершает воркер и сразу запускает новый (код 130, `среда перезапущена, переменные сброшены`). Команда дольше `timeoutMs` заканчивается так же, с кодом 124.
- Строка, начинающаяся с `#`, здесь — синтаксическая ошибка: вставленные строки и строки из `run()` уходят в бэкенд, см. раздел [Терминал](#терминал).

| Опция | По умолчанию | Значение |
| --- | --- | --- |
| `timeoutMs` | `10000` | Ограничение на команду по реальному времени; `0`, отрицательное или нечисловое значение его снимает |
| `initTimeoutMs` | `10000` | Сколько воркер может готовиться к работе |
| `outputLimit` | `1048576` | Символов вывода на команду; остальное отбрасывается с пометкой |
| `globals` | нет | Значения, которые появятся в воркере; копируются один раз через `structuredClone`, поэтому функции и объекты DOM не принимаются |
| `baseURL` | `document.baseURI` при каждом старте воркера | База для относительных URL |
| `prompt` | `'> '` | Приглашение |
| `banner` | нет | Печатается, когда воркер готов |
| `createWorker` | воркер по `blob:`-адресу с `WORKER_SOURCE` | Ваш собственный воркер |

Свой `createWorker` должен говорить на протоколе 0.8: хост отправляет `{ type: 'init', globals, baseURL }`, затем `{ type: 'run', id, code, declarations, columns, outputLimit }`; воркер отвечает `{ type: 'ready', evalBlocked }`, `{ type: 'log', id, text }` и `{ type: 'result', id, value?, error? }` (типы `HostMessage` и `WorkerMessage`). Проще всего запустить в своём воркере экспортированный `WORKER_SOURCE`, например отдав его файлом со своего домена вместо `blob:`-адреса; воркер, загруженный по URL, подчиняется CSP из собственного HTTP-ответа. Тип воркера — общий `WorkerLike` без зависимости от DOM, поэтому настоящий `Worker` подходит без приведения типов.

### `docsterm/pyodide`

CPython, скомпилированный в WebAssembly ([Pyodide](https://pyodide.org)), в модульном Web Worker: бесконечный цикл не подвешивает страницу, а Python не видит ни DOM страницы, ни её `localStorage`.

```ts
import { createPyodideBackend } from 'docsterm/pyodide'

const backend = createPyodideBackend({ packages: ['micropip', 'numpy'] })
```

- Баннер показывает настоящие версии (`Python 3.x (pyodide 314.0.7)`); результаты выражений печатаются через `repr()`, `_` хранит последний.
- Блоки продолжаются с приглашением `'... '` и заканчиваются пустой строкой; `await` верхнего уровня работает.
- Импорт пакетов из поставки Pyodide (numpy, pandas…) подгружает их сам.
- `pip install <пакет>` (а также `%pip` и `!pip`; принимаются `-q`, `--pre`, `--no-deps` и `-U`) ставит через micropip pure-Python-пакеты с PyPI и пакеты Pyodide.
- `input()` печатает своё приглашение и выбрасывает `EOFError: чтение ввода в этом терминале не поддерживается`.
- `exit()`, `quit()` и `sys.exit(n)` завершают команду с кодом `n & 0xFF` (`True` — это 1; нецелый код печатается и даёт 1).
- Файлы живут в памяти Pyodide и пропадают при перезагрузке страницы или перезапуске среды.
- После Ctrl+C терминал показывает только `^C`, как и с другими бэкендами.
- В продакшене размещайте среду у себя и указывайте `indexURL`: с CDN файлы загружаются без проверки целостности.

Что делает Ctrl+C, зависит от межсайтовой изоляции — отдаёт ли сервер страницу с заголовками `Cross-Origin-Opener-Policy: same-origin` и `Cross-Origin-Embedder-Policy: require-corp` (тогда каждому ресурсу с другого источника нужен CORS или `Cross-Origin-Resource-Policy`):

| Что выполняется | Страница изолирована | Не изолирована |
| --- | --- | --- |
| Бесконечный цикл | `KeyboardInterrupt`, переменные на месте | через 0,5 с среда перезапускается, переменные теряются |
| `await`, задачи asyncio | `KeyboardInterrupt`, переменные на месте | отменяются на месте, переменные на месте |
| `time.sleep()` | `KeyboardInterrupt`, переменные на месте | прерывается на месте там, где браузер поддерживает JSPI (Chromium); в остальных — перезапуск, как у цикла |

Если команда не остановилась через 0,5 с после Ctrl+C (при изоляции — через 3 с), среда перезапускается и печатает `среда перезапущена, переменные сброшены`. Голый `run_sync(promise)` отменить нельзя, он всегда заканчивается так. Вывод фоновых задач прошлой команды попадает в ту команду, что выполняется в этот момент, а неоконченная строка, напечатанная между командами, появляется в конце следующей.

| Опция | По умолчанию | Значение |
| --- | --- | --- |
| `indexURL` | `https://cdn.jsdelivr.net/pyodide/v314.0.7/full/` | Откуда грузится среда. Относительное значение считается от `document.baseURI`. В собственной папке нужны `pyodide.mjs`, `pyodide.asm.mjs`, `pyodide.asm.wasm`, `python_stdlib.zip`, `pyodide-lock.json` и нужные вам пакеты |
| `packages` | `['micropip']` | Загружаются при старте; список заменяет значение по умолчанию; ошибки загрузки старт не срывают |
| `prompt` | `'>>> '` | Приглашение |
| `createWorker` | модульный воркер по `blob:`-адресу | `(source) => WorkerLike`; например, модульный воркер со своего домена с `PYODIDE_WORKER_SOURCE`, если CSP запрещает `blob:`-воркеры. Глобальный объект воркера должен поддерживать `addEventListener` для `error` и `unhandledrejection` (любой браузерный воркер умеет) |

Другие экспорты: `DEFAULT_PYODIDE_VERSION` (`'314.0.7'`, он же `PYODIDE_VERSION`), `PYODIDE_WORKER_SOURCE`, тип `PyodideWorker` и `formatPythonError`, которым бэкенд больше не пользуется.

### `docsterm/wasi`

Запускает одну программу, собранную под `wasm32-wasi`, на собственной реализации WASI preview1.

```bash
cargo build --release --target wasm32-wasip1     # Rust
zig build-exe -target wasm32-wasi main.zig       # Zig
GOOS=wasip1 GOARCH=wasm go build -o greet.wasm    # Go
```

```ts
import { createWasiBackend } from 'docsterm/wasi'

const backend = createWasiBackend({
  url: '/greet.wasm',
  program: 'greet',
  usage: 'greet <name>',
  env: { RUST_LOG: 'info' },
})
```

Читатель набирает `greet "Ada Lovelace"`. Работают аргументы, переменные окружения, stdout и stderr (по порядку и потоком), коды возврата, часы, сон и случайные числа. Стандартный ввод — фиксированная опция `stdin`: то, что набирает читатель, до программы не доходит. Остальные вызовы WASI (файлы, сокеты…) возвращают `ENOSYS`, поэтому программа запускается и сама уходит в свою обработку ошибки: `std::fs` в Rust возвращает ошибку, `os.ReadFile` в Go падает, а hello world, разбор аргументов и `thread::sleep` работают.

- Одна программа на строку. Кавычки, экранирование обратной косой чертой и комментарии `#` работают; `\` в конце или открытая кавычка продолжают ввод с приглашением `'> '`; пустые строки и строки из одного комментария допустимы.
- Конвейеры, перенаправления, `&&`, `;`, переменные, обратные кавычки, скобки и вторая команда на другой строке дают `конвейеры, перенаправления и переменные в этом терминале не поддерживаются` (код 2). Чужое имя программы даёт `name: команда не найдена (этот терминал запускает greet)` (код 127).
- Каждая команда получает новый экземпляр, так что один запуск не может испортить следующий.
- Программы работают в Web Worker: Ctrl+C их останавливает (код 130), а `timeoutMs` прерывает бесконечные циклы (код 124); ловушка (trap) даёт код 1. На странице без межсайтовой изоляции `sleep` ждёт активно внутри воркера: одно ядро процессора занято, страница — нет.
- Молчаливого перехода на страницу нет. Если воркер не запускается (CSP запрещает `blob:`-воркеры, в среде нет `Worker`, свой воркер падает или не сообщил о готовности за `initTimeoutMs`), `init()` отклоняется или команды завершаются с кодом 1 и локализованной причиной, например `заблокировано политикой Content-Security-Policy страницы (нужно worker-src blob:)`. Chromium сообщает о заблокированном `blob:`-воркере с опозданием, поэтому причина может появиться при первой команде, а не при старте.
- На самой странице программы работают только с `worker: false` или своим `instantiate`. Тогда страница заблокирована, пока программа работает, Ctrl+C её не остановит, ограничение времени проверяется только на системных вызовах, `sleep` ждёт активно, а чисто вычислительный цикл подвесит вкладку.

| Опция | По умолчанию | Значение |
| --- | --- | --- |
| `url`, `bytes`, `instantiate` | — | Откуда берётся модуль (нужно одно из трёх). `url` скачивается и компилируется один раз при старте; HTTP-ошибка или HTML-страница срывают старт (`не удалось скачать …: HTTP 404`, `это не модуль WebAssembly: …`) |
| `program` | `main` | Имя команды, которое набирает читатель |
| `args` | `[]` | Аргументы перед аргументами читателя |
| `env` | `{}` | Переменные окружения |
| `stdin` | `''` | Фиксированный стандартный ввод каждого запуска |
| `usage` | нет | Строка использования для `help` и AI |
| `prompt` | `'$ '` | Приглашение |
| `banner` | нет | Печатается один раз при старте |
| `timeoutMs` | `30000` | Ограничение на команду; `0`, отрицательное или нечисловое значение его снимает |
| `initTimeoutMs` | `10000` | Сколько воркер может запускаться; после этого команды завершаются с `WebAssembly-воркер не запустился за … с` |
| `outputLimit` | `1048576` | Символов вывода на команду; после пометки остальное отбрасывается, а программа работает дальше |
| `worker` | `true` | `false` запускает программы на странице (см. выше) |
| `createWorker` | воркер по `blob:`-адресу | `(source) => WorkerLike`, например файл со своего домена с `WASI_WORKER_SOURCE` |

Коды возврата: статус программы `& 255`; 1 — ловушка или упавший воркер; 2 — отвергнутая командная строка; 124 — ограничение времени; 127 — чужое имя программы; 130 — Ctrl+C. Другие экспорты: `createWasiHost`, `splitCommandLine` (бросает `CommandLineError`), `isCompleteCommandLine`, `WASI_WORKER_SOURCE`.

### `docsterm/websocket`

Отправляет команды на ваш сервер. [Сервер-образец](../examples/websocket-server/README.ru.md) даёт каждому читателю одноразовый Docker-контейнер и настоящий псевдотерминал; прочтите его раздел о безопасности, прежде чем что-либо разворачивать.

```ts
import { createWebSocketBackend } from 'docsterm/websocket'

const backend = createWebSocketBackend({
  url: 'wss://sandbox.example.com/',
  prompt: 'sandbox:~$ ',
  description: 'An Alpine Linux container with git and curl.',
})
```

| Опция | По умолчанию | Значение |
| --- | --- | --- |
| `url` | — | Адрес сервера (на HTTPS-страницах — `wss://`) |
| `protocols` | нет | Подпротоколы WebSocket |
| `prompt` | `'$ '` | Приглашение, пока сервер не прислал своё (возможность `prompt`) |
| `banner` | нет | Печатается при первом подключении |
| `description` | нет | Текст для `help` и AI |
| `token` | нет | Отправляется как `{"type":"auth","token":…}`, первым сообщением в каждом новом сокете |
| `timeoutMs` | `120000` | Только протокол v1: команда, которая столько молчит, отменяется (код 124); `0` снимает ограничение |
| `connectTimeoutMs` | `15000` | Ограничение на открытие сокета |
| `readyTimeoutMs` | `1500` | Сколько `init()` ждёт `ready` после открытия сокета |
| `createSocket` | `new WebSocket(url, protocols)` | Свой сокет; DOM-`WebSocket` подходит к `SocketLike` без приведения типов |

**Протокол v1** (любой сервер). Все кадры — текстовый JSON.

| Направление | Сообщение | Значение |
| --- | --- | --- |
| клиент → сервер | `{"type":"run","id":1,"command":"ls -l","locale":"ru"}` | выполнить команду; необязательный `locale` (`en` или `ru`) позволяет серверу локализовать свои уведомления, а сервер, который не знает это поле, его пропускает |
| клиент → сервер | `{"type":"cancel","id":1}` | остановить команду 1 (Ctrl+C, ограничение времени) |
| клиент → сервер | `{"type":"auth","token":"…"}` | первое сообщение, только с опцией `token` |
| сервер → клиент | `{"type":"ready","banner":"…"}` | сеанс открыт; `banner` необязателен |
| сервер → клиент | `{"type":"output","id":1,"chunk":"…"}` | вывод команды 1 |
| сервер → клиент | `{"type":"exit","id":1,"code":0}` | команда 1 завершилась |

**Протокол v2** добавляет, если `ready` несёт `"protocol":2` и `features`:

| Направление | Сообщение | Значение |
| --- | --- | --- |
| сервер → клиент | `{"type":"ready","protocol":2,"features":["pty","resize","prompt","ping"],"prompt":"sandbox:~$ "}` | возможности сервера; `prompt` необязателен |
| клиент → сервер | `{"type":"run","id":1,"command":"vi","columns":80,"rows":24}` | `columns`/`rows` отправляются при `pty` или `resize` |
| клиент → сервер | `{"type":"stdin","id":1,"data":"y\r"}` | сырые нажатия для выполняющейся команды |
| клиент → сервер | `{"type":"resize","columns":120,"rows":40}` | терминал изменил размер во время команды с pty |
| клиент → сервер | `{"type":"ping"}` | проверка связи |
| сервер → клиент | `{"type":"exit","id":1,"code":0,"prompt":"sandbox:~/app$ "}` | `prompt` следует за рабочим каталогом |
| сервер → клиент | `{"type":"pong"}` | ответ на `ping` |

- `pty`: `run()` возвращает интерактивный запуск. Каждое нажатие, включая Ctrl+C, уходит на сервер как `stdin`: удалённая дисциплина линии сама выводит эхо, редактирует строку и превращает Ctrl+C в SIGINT; второй Ctrl+C в течение секунды отправляет `cancel`. Вывод попадает в xterm без изменений, поэтому работают `vi`, `top`, `less` и вопросы `read`. У команд с pty нет клиентского ограничения времени — действует лимит сервера.
- `resize`: изменения размера во время команды с pty отправляются сразу; изменение в простое доходит до сервера в `columns`/`rows` следующей команды.
- `prompt`: приглашение виджета следует за `ready.prompt` и `exit.prompt`.
- `ping`: клиент проверяет связь каждые 20 с, а любое корректное сообщение сервера считается признаком жизни. После 60 с тишины выполняющаяся команда завершается с `сервер перестал отвечать, соединение разорвано` (код 1), и клиент переподключается через 0,5, 1, 2, 4 и 8 с, сообщая о каждой попытке. После пяти неудач попробует следующая команда; переподключение к серверу v2 сообщает, что начался новый сеанс.

Правила для сервера:

- Возвращайте `id` в каждом `output` и `exit`. Сообщения без id (или с `null`) принимаются, только пока ни одна отменённая команда не ждёт своего `exit`.
- Отвечайте на `cancel` сообщением `exit` (по соглашению с кодом 130).
- Отправляйте `ready` сразу после принятия соединения.

Что делает клиент:

- `init()` завершается по `ready` или через `readyTimeoutMs` после открытия сокета — что наступит раньше; пока `ready` не пришёл, клиент говорит на v1, а баннер из запоздавшего `ready` печатается над приглашением.
- Осторожная проверка по правилам POSIX (кавычки, `$( )`, обратные кавычки, here-документы, `if`/`case`/циклы, `{ }`, `( )`, `\`, `|`, `&&`, `||` в конце) оставляет незаконченную команду открытой с приглашением `'> '`, а строки уходят на сервер одной командой. Проверка склоняется к «команда закончена», так что настоящая синтаксическая ошибка придёт от сервера; Ctrl+C сбрасывает незаконченную команду. Программа на сервере, которая не является оболочкой, получает те же правила.
- Когда сервер закрывает соединение, терминал печатает `сервер закрыл соединение (code: reason)`, выполняющаяся команда завершается с кодом 1, а следующая команда один раз переподключается (`переподключаюсь...`) или падает с `нет соединения с сервером`. Возможности, протокол и приглашение сбрасываются при каждом разрыве. Команда, набранная, пока автоматическое переподключение ждёт `ready`, дождётся его (или `readyTimeoutMs`), прежде чем выбрать v1 или v2.
- Ошибки подключения показывают только схему, хост, порт и путь адреса сервера; токены, учётные данные и фрагменты не печатаются никогда.

[Сервер-образец](../examples/websocket-server/README.ru.md) говорит на v2 и добавляет собственные ограничения, все настраиваемые. Его уведомления начинаются с `docsterm-server:` и следуют `locale` команды. `ready` может прийти без приглашения — тогда оно придёт с первым `exit`. Сеанс заканчивается через 30 минут с уведомлением и кодом закрытия 1000; клиент, который перестал читать вывод, отключается (браузер видит код закрытия 1006); ввод сверх бюджета скорости, например очень длинная вставка, отбрасывается.

Токен виден каждому скрипту на странице и самому читателю. Выдавайте короткоживущие токены на каждого читателя из бэкенда своей документации и передавайте токен опцией `token`, а не параметром `?token=` в URL: URL оседают в логах. Песочница, все ограничения и их настройки описаны в [README сервера-образца](../examples/websocket-server/README.ru.md).

import { createMockBackend } from 'docsterm/mock'

const backend = createMockBackend({

## Терминал

Терминал — это xterm.js под управлением строкового редактора, с потоковым выводом, отменой и полноэкранными программами.

| Клавиши | Действие |
| --- | --- |
| Enter | Выполнить строку или продолжить многострочную команду |
| ← → | Курсор на символ (также Ctrl+B, Ctrl+F) |
| Alt+← Alt+→, Ctrl+← Ctrl+→ | Курсор на слово (также Alt+B, Alt+F) |
| Home End | В начало или в конец строки (также Ctrl+A, Ctrl+E) |
| Backspace, Delete | Удалить символ до или после курсора (Ctrl+D удаляет после) |
| Ctrl+W, Ctrl+Backspace, Alt+Backspace | Удалить предыдущее слово |
| Alt+D, Ctrl+Delete | Удалить следующее слово |
| Ctrl+U, Ctrl+K | Удалить до начала, до конца |
| Ctrl+Y | Вставить последний удалённый текст |
| Ctrl+T | Поменять местами два символа перед курсором |
| ↑ ↓ | Листать историю |
| Tab | Дополнить (если бэкенд умеет): один вариант вставляется, общий префикс дописывается, несколько вариантов выводятся списком |
| Ctrl+L | Очистить экран, сохранив строку |
| Ctrl+C | Остановить команду, запрос к AI или вопрос y/N; иначе сбросить строку |
| Ctrl+Shift+C, Ctrl+Shift+V | Копировать, вставить |
| Shift+Tab или Esc, затем Tab | Увести фокус из терминала |

В Windows и Linux Ctrl+C при выделении копирует, а Ctrl+F, Ctrl+P, Ctrl+S и Ctrl+G достаются браузеру, если не работает интерактивная программа. В macOS Option+буква печатает символ, поэтому там пользуйтесь сочетаниями со стрелками. Поиска по Ctrl+R нет.

- **История** хранит 200 строк: набранные, вставленные и пришедшие из `run()`, каждую строку многострочной команды и принятые однострочные команды AI; пустые строки, повтор предыдущей строки и ответы y/N не попадают. Правки вызванной из истории строки сохраняются до Enter. Встроенная команда `history` выводит список.
- **Встроенные команды** поверх любого бэкенда: `help` (команды, клавиши и описание бэкенда), `clear`, `history`, `explain` (объяснение AI для последней упавшей команды) и `#<запрос>`. Они срабатывают, только если строка состоит из одного этого слова: `help;` или `print(help)` уходят в бэкенд — так можно прочитать переменную REPL с именем `help`. Как и `#`, `explain` обращается к AI, только если его набрали: из вставки, `run()` или кнопки запуска он уходит в бэкенд.
- **Вставка** идёт через bracketed paste: переводы строк приводятся к одному виду, управляющие последовательности и символы отбрасываются, табуляция становится четырьмя пробелами, и каждая строка выполняется по очереди под своим приглашением. Вставка — одно целое от первого маркера начала до последнего маркера конца, поэтому текст в буфере обмена с поддельным концом вставки из неё не вырвется.
- **Ввод наперёд**: нажатия во время работы команды появятся у следующего приглашения; нажатия до того, как интерактивная программа перехватит ввод, достаются ей. Всё, что набрано или вставлено до появления вопроса y/N, отбрасывается.
- **Вывод в простое** (запоздавшая строка лога, уведомление сервера) печатается над приглашением, а набираемая строка сохраняется.
- **Полноэкранные программы** получают сырые нажатия и могут пользоваться альтернативным экраном. Вставка доходит до программы в том виде, в каком её отправляет xterm, а маркеры bracketed paste добавляются, только если программа сама их включила. Когда программа заканчивается, виджет при необходимости уходит с альтернативного экрана и сбрасывает режимы терминала перед следующим приглашением.
- **Сообщения виджета** (приветствие, справка, ошибки, пояснения AI) переносятся по словам под ширину терминала; вывод бэкенда, предложенные команды и строки истории печатаются как есть.

### Вопросы к AI

Если провайдер AI настроен:

- `#<запрос>`, например `#найди большие логи`: AI отвечает одной командой и пояснением в одно предложение. Сначала печатается пояснение, команда — прямо над `выполнить? [y/N]`, и ничего не выполняется без `y` или `yes` (с русской локалью — ещё `д` или `да`). Команда выше экрана отвергается.
- `explain` потоком объясняет последнюю упавшую команду по первым 500 и последним 1500 символам её вывода.
- AI видит заголовок, описание и подзаголовки страницы, описание бэкенда и последние пять команд.

**`#` спрашивает AI только для набранных строк.** Строка уходит к AI, только если её первый непробельный символ набрал читатель: если набрать `#` и вставить вопрос, запрос всё равно уйдёт к AI, а строка из истории считается набранной. Строки из вставки, `run()`, `insert()` или кнопки запуска уходят в бэкенд без изменений: в sh и Python `#` — комментарий, так что вставленные фрагменты с комментариями никогда не запускают платные запросы. В бэкенде JavaScript такая строка — синтаксическая ошибка. Без провайдера AI любая строка с `#` уходит в бэкенд.

## Провайдеры AI

У `AIProvider` два метода, `suggestCommand` и `explainError`. В пакете два провайдера, а `createMockAIProvider` из `docsterm` годится для офлайн-демо и тестов.

```ts
import { createAnthropicProvider } from 'docsterm/anthropic'
import { createOpenAIProvider } from 'docsterm/openai'

const claude = createAnthropicProvider()
const openRouter = createOpenAIProvider({ preset: 'openrouter', model: 'openai/gpt-6-luna' })
const localModel = createOpenAIProvider({ preset: 'ollama', model: 'llama3.2' })
const gateway = createOpenAIProvider({ baseURL: 'https://gateway.example.com/v1', model: 'internal-fast' })

export const providers = [claude, openRouter, localModel, gateway]
```

### Anthropic

`createAnthropicProvider(options)` работает через официальный SDK в браузерном режиме; SDK загружается при первом запросе.

| Опция | По умолчанию | Значение |
| --- | --- | --- |
| `apiKey` | ключ читателя из `localStorage` (`docsterm:anthropic-key`), только для api.anthropic.com | Ключ API |
| `baseURL` | api.anthropic.com | Другой адрес, например ваш прокси; ключ не нужен, а сохранённый ключ читателя туда не отправляется никогда |
| `model` | `claude-opus-5-5` | Модель |
| `maxTokens` | `8192` | Ограничение ответа |
| `effort` | `'low'` для моделей с поддержкой effort, иначе не отправляется | `'low'`, `'medium'`, `'high'`, `'xhigh'`, `'max'` или `false` |
| `fallbacks` | включено для Fable 5.1, Mythos, Opus 5.x и Sonnet 5.5 | Запасные модели на стороне сервера (`fallbacks: 'default'` с бета-заголовком `server-side-fallback-2026-07-01`); Bedrock, Vertex AI и Foundry это отвергают, там передавайте `false` |
| `clientFactory` | клиент SDK в браузерном режиме | `(apiKey) => client` или промис клиента; настоящий экземпляр `Anthropic` подходит без приведения типов. Если ключ не задан, получает `undefined` и тогда не должен отправлять учётные данные |

Модели с поддержкой effort: Opus 4.5 и новее, Sonnet 4.6 и новее, Haiku 5.5 и новее, Fable, Mythos. Подсказки запрашивают структурированный JSON, объяснения приходят потоком. Если API отвечает 400 и называет `effort`, формат ответа или `fallbacks`, провайдер один раз повторяет запрос без этого поля и помнит отказ до перезагрузки страницы. Если отброшен формат, промпт сам описывает нужный JSON. Запомненный отказ может скрыть ошибку настройки, например `effort: 'xhigh'` для модели без такого уровня.

| `together` | `https://api.together.xyz/v1` | `max_tokens` | object |
| `xai` | `https://api.x.ai/v1` | `max_tokens` | object |
| `gemini` | `https://generativelanguage.googleapis.com/v1beta/openai` | `max_tokens` | object |
| `ollama` | `http://localhost:11434/v1` | `max_tokens` | object, ключ не нужен |
| `lmstudio` | `http://localhost:1234/v1` | `max_tokens` | schema, ключ не нужен |
| свой `baseURL` | — | `max_tokens` | object |

Если запрос подсказки получает 400 и в теле ответа упомянут `response_format`, он отправляется ещё раз без него, а ответ тогда читается из свободного текста. Ключ читателя привязан к адресу: `defaultKeyName({ preset, baseURL })` возвращает ячейку для него (`docsterm:key:openai` для OpenAI). Ячейка версии 0.7 `docsterm:openai-key` больше не читается, потому что в ней мог лежать ключ другого поставщика; `OPENAI_KEY_NAME` по-прежнему экспортируется, но не используется. Своему `baseURL`, если это не адрес одного из облачных пресетов, ключ не нужен, а без ключа заголовок `Authorization` не отправляется.

### Локальные модели

Пресеты `ollama` и `lmstudio` обращаются к модели на компьютере читателя без ключа. Опубликованному сайту документации нужно три вещи:

- Ollama по умолчанию принимает запросы с других источников только от `localhost`. Читатель запускает её с разрешением для вашего адреса: `OLLAMA_ORIGINS=https://docs.example.com ollama serve`.
- В LM Studio нужно включить CORS в настройках локального сервера.
- Local Network Access в Chrome спрашивает у читателя разрешение, когда публичный сайт впервые обращается к `localhost`. Если он откажет, запрос упадёт с `не удаётся связаться с сервисом AI.`

### Ключи, ошибки и ответы

Ключи приносит читатель. Его ключ хранится в его `localStorage` в ячейке, описанной выше (`keyStore.set(name, value)` и `keyStore.clear(name)` из `docsterm` управляют ею; форма настроек — в `demo/src/ai-settings.ts`), и уходит только по настроенному адресу. Любой скрипт с вашего источника может прочитать `localStorage`, так что XSS или сторонний скрипт способны его украсть. Никогда не кладите свой ключ в `apiKey` на публичной странице: любой читатель достанет его из бандла. Чтобы оплачивать запросы читателей самостоятельно, поднимите прокси, который подставляет ключ на сервере, и направьте провайдер на него; ключ в браузере тогда не нужен ни одному провайдеру:

```ts
import { createAnthropicProvider } from 'docsterm/anthropic'
import { createOpenAIProvider } from 'docsterm/openai'

export const viaAnthropicProxy = createAnthropicProvider({ baseURL: 'https://docs.example.com/api/anthropic' })

export const viaOpenAIProxy = createOpenAIProvider({
  baseURL: 'https://docs.example.com/api/openai/v1',
  model: 'gpt-6-luna',
})
```

Запрос к Anthropic без ключа не отправляет ни `x-api-key`, ни `Authorization`.

Ошибки показываются на языке читателя. У отсутствующего ключа, отказа, оборванного ответа, пустого или негодного ответа и сетевой ошибки — свои сообщения. Ошибка сервера выглядит как `запрос к AI не удался: <статус>: <сообщение>`, где сообщение берётся из `error.message`, строкового `error`, `message` или строкового `detail` ответа (очищенное, в одну строку, не длиннее 300 символов); для HTML и пустого тела показывается `сервис AI сообщил об ошибке`. Провайдеры бросают `AIProviderError` с полем `code` (`key-missing`, `refused`, `truncated`, `empty`, `invalid`, `http`, `network`), а после отмены — DOM-ошибку `AbortError`.

Из подсказки оба провайдера берут первый JSON-объект с непустой строкой `command`, не обращая внимания на текст вокруг. Из команды удаляются управляющие последовательности и символы; команда длиннее 2000 символов отвергается, как и команда с невидимыми или форматирующими символами (управление направлением текста, символы нулевой ширины, разделители строк, неназначенные кодовые точки): из-за них команда на экране может отличаться от выполняемой. По той же причине отвергаются эмодзи, склеенные символом нулевой ширины. Из пояснения такие символы просто удаляются. Многострочная команда показывается построчно и уходит в бэкенд одной строкой.

## Управляющий API

Страница может управлять терминалом: выполнить команду из блока кода, подставить команду, которую читатель допишет сам, или узнать, где читатели спотыкаются.

```ts
import '@xterm/xterm/css/xterm.css'
import { DocsTerminal, isAbortError, type DocsTerminalEvent } from 'docsterm'
import { createShellBackend } from 'docsterm/shell'

const terminal = new DocsTerminal({
  backend: createShellBackend({ cwd: '/project' }),
  onEvent: (event: DocsTerminalEvent) => {
    if (event.type === 'command' && event.exitCode !== 0) console.info('failed:', event.command)
  },
})

const container = document.querySelector<HTMLElement>('#terminal')
if (container) terminal.mount(container).catch((error: unknown) => console.error(error))

try {
  const report = await terminal.run('mkdir -p app && cd app && pwd')
  console.info(report.exitCode, report.output)
} catch (error) {
  if (!isAbortError(error)) throw error
}

terminal.insert('orbit deploy --env ')
terminal.focus()
```

| Метод или свойство | Что делает |
| --- | --- |
| `mount(element)` | Открывает терминал внутри `element` и запускает бэкенд. Завершается, когда показано первое приглашение. Сразу бросает ошибку, если терминал уже смонтирован; отклоняется с ошибкой бэкенда (она же печатается в терминале с советом перезагрузить страницу) или с `AbortError`, если раньше вызван `dispose()` |
| `run(text)` | Выполняет `text`, как будто его вставили и нажали Enter; возвращает `RunReport` |
| `insert(text)` | Впечатывает `text` в позицию курсора без Enter; переводы строк становятся пробелами |
| `clear()` | Очищает экран и прокрутку, сохраняя набранную строку |
| `focus()` | Переводит фокус в терминал |
| `element` | Собственный элемент терминала внутри вашего контейнера или `null` |
| `setOptions(patch)` | Меняет опции на лету, см. [Опции виджета](#опции-виджета) |
| `setTheme`, `setLocale`, `setAI`, `setPageContext`, `setOnEvent` | Сокращения для одной опции |
| `dispose()` | Убирает терминал, отменяет работу и освобождает бэкенд, если тот был запущен. Тот же экземпляр можно снова смонтировать через `mount()` |

**`run(text)`**

- Многострочный текст выполняется построчно, продолжение строк работает. Один завершающий перевод строки отбрасывается. Если текст оставляет многострочную команду незаконченной, добавляется одна пустая строка — она закрывает блок Python: `'for i in range(3):\n    print(i)'` выполнится. Если команда всё равно не закончена, ничего не выполняется: терминал печатает `^C`, промис выполняется с кодом 2, а событие `error` (фаза `'run'`) сообщает `незавершённая команда: ей нужны ещё строки, поэтому она не выполнена`.
- Табуляция сохраняется и показывается четырьмя пробелами.
- До монтирования, пока стартует бэкенд и пока терминал занят, строки ждут в очереди ввода.
- Пока на экране вопрос y/N или полноэкранная программа, ввод через API ждёт: он никогда не отвечает на вопрос и не попадает в программу. Нажатия читателя при этом проходят.
- Недонабранная читателем строка и незаконченная многострочная команда откладываются и возвращаются после последней строки, так что щелчок по блоку с `/tmp/x`, когда читатель уже набрал `rm -rf` и пробел, никогда не выполнит `rm -rf /tmp/x`. Если читатель печатает во время выполнения, побеждает новый ввод, а отложенная строка уходит в историю, где её найдёт ↑. `insert()`, наоборот, вставляет текст в строку читателя.
- Промис выполняется с `{ exitCode, output }` последней команды. Ctrl+C отбрасывает ждущие строки и выполняет промис с кодом 130 и частичным выводом текущей команды. `help`, `clear` и `history` сообщают 0 и напечатанный текст; `explain` и строки с `#` уходят в бэкенд.
- `output` — то, что команда напечатала на обычном экране, плюс её возвращённый вывод, без управляющих последовательностей и символов, последние 4096 символов. Вывод на альтернативном экране (`less`, `vi`) не входит.
- `dispose()` отклоняет ждущие и выполняющиеся вызовы с `AbortError` (проверяйте через `isAbortError`), а последующие вызовы отклоняются до следующего `mount()`. После неудачного монтирования вызовы отклоняются с ошибкой монтирования.

**События** (опция `onEvent`, `setOnEvent()` или `setOptions({ onEvent })`):

| Событие | Поля | Когда |
| --- | --- | --- |
| `ready` | — | Бэкенд запущен, до первого приглашения и до завершения `mount()` |
| `command` | `command`, `source`, `exitCode`, `durationMs` | Команда завершилась, включая `help`, `clear` и `history`. `source` — `'typed'`, `'paste'`, `'api'` или `'ai'`; многострочная команда сообщает строки, соединённые `\n` |
| `interrupt` | `command?` | Ctrl+C, пока что-то выполняется: с `command` для команды или программы (считается каждый Ctrl+C, отправленный программе), без него для запроса к AI. Не возникает у пустого приглашения и при продолжении строки |
| `ai-suggest` | `request`, `command?`, `accepted?` | Запрос `#` завершён: ответ y/N (`command`, `accepted`), Ctrl+C на вопросе (`accepted: false`) или ошибка и негодный ответ (без `command`) |
| `ai-explain` | `command` | `explain` начал объяснять последнюю упавшую команду |
| `error` | `phase`, `message` | `'init'`: монтирование не удалось (но не когда его прервал `dispose()`); `'run'`: бэкенд бросил ошибку или текст `run()` остался незаконченным; `'ai'`: запрос к AI не удался |

Порядок: принятая подсказка даёт `ai-suggest`, затем `command` с источником `'ai'`; ошибка бэкенда — `error` (`'run'`), затем `command` с кодом 1; ошибка AI — `error` (`'ai'`), затем `ai-suggest` без `command`. `explain` порождает `ai-explain` (и `error`, если запрос не удался), но не `command`. Исключение в вашем обработчике пишется в консоль и никогда не ломает сеанс.

**Приватность.** События несут текст команд, `ai-suggest` — запрос читателя, сообщения об ошибках могут повторять ввод, а `RunReport.output` — содержать всё, что читатель вывел, включая секреты. Что из этого отправлять в аналитику, решаете вы.

## Кнопки запуска

`attachRunButtons(root, terminal, options?)` добавляет кнопку запуска к блокам кода.

```html
<pre data-docsterm-run><code>$ orbit init
Project initialized.
$ orbit deploy</code></pre>
```

```ts
import { attachRunButtons, DocsTerminal } from 'docsterm'
import { createShellBackend } from 'docsterm/shell'

const terminal = new DocsTerminal({ backend: createShellBackend() })
const container = document.querySelector<HTMLElement>('#terminal')
if (container) terminal.mount(container).catch((error: unknown) => console.error(error))

const detach = attachRunButtons(document.body, terminal)
window.addEventListener('pagehide', detach, { once: true })
```

- Селектор по умолчанию — `pre[data-docsterm-run] code, code[data-docsterm-run]`; другой передаётся в `selector`, например `'pre > code.language-bash'`.
- Если в блоке есть строки, начинающиеся с приглашения (`prompts`, по умолчанию `['$ ', '% ']`), выполняются только эти команды, без приглашения; остальные строки считаются показанным выводом. Команда продолжается на следующей строке после `\` в конце или на строках, начинающихся с `>` и пробела. Блок без приглашений выполняется целиком.
- Строки читаются так, как блок выглядит на экране: `<br>` и строчные элементы (`div`, `p`, `li` и классы `.token-line`, `.ec-line` и `.line` из Docusaurus, Expressive Code и Shiki) заканчивают строку. Скрытый от читателя текст (`hidden`, `aria-hidden="true"`, `display: none`, `visibility: hidden`) не выполняется никогда; блок внутри закрытой вкладки или `<details>` свою кнопку сохраняет. Блок без команды кнопку не получает.
- Кнопка — `<button type="button" class="docsterm-run">` в общем `span.docsterm-run-bar` в правом верхнем углу `<pre>`, так что кнопки от разных вызовов не накладываются друг на друга. Надпись — `запустить` (`run` по-английски), а в `aria-label` названа первая команда. Язык берётся из опции `locale`, иначе из ближайшего атрибута `lang`, иначе из языка браузера.
- Щелчок прокручивает к терминалу, переводит в него фокус и вызывает `run()`; до конца выполнения кнопка неактивна.
- На документ (или теневой корень) добавляется одна небольшая таблица стилей, она удаляется с последней очисткой. Её правила обёрнуты в `:where()`, так что ваш CSS сильнее. С `styles: false` ничего не внедряется, а `.docsterm-run` вы оформляете сами — например, если CSP запрещает встроенные стили.
- За страницей никто не следит. После навигации на клиенте вызовите возвращённую функцию очистки и подключите кнопки заново; блок, у которого уже есть кнопка, пропускается.
- `terminal` — всё, у чего есть `run(text)` и `focus()`: `DocsTerminal`, элемент `<docs-terminal>` или ref-хэндл React. К терминалу прокручивается, если у него есть `element` или он сам — элемент.

## React

```tsx
import '@xterm/xterm/css/xterm.css'
import { useRef, useState } from 'react'
import type { DocsTerminalEvent } from 'docsterm'
import { DocsTerminal, type DocsTerminalHandle } from 'docsterm/react'
import { createShellBackend } from 'docsterm/shell'

export function ShellTutorial({ dark }: { dark: boolean }) {
  const [backend] = useState(() => createShellBackend({ cwd: '/project' }))
  const terminal = useRef<DocsTerminalHandle>(null)
  const track = (event: DocsTerminalEvent) => {
    if (event.type === 'error') console.warn(event.message)
  }
  return (
    <>
      <button type="button" onClick={() => void terminal.current?.run('ls -la')}>
        list files
      </button>
      <DocsTerminal
        ref={terminal}
        backend={backend}
        theme={dark ? 'dark' : 'light'}
        aria-label="Project shell"
        onEvent={track}
        style={{ height: 320 }}
      />
    </>
  )
}
```

- Пропсы — это [опции виджета](#опции-виджета), а также `onReady(terminal)`, `onError(error)` и атрибуты контейнера `id`, `title`, `role`, `className`, `style`, `aria-*` и `data-*`. `aria-label` подписывает сам терминал, если не задан `ariaLabel`.
- Новый объект `backend` перемонтирует терминал и стирает сеанс, поэтому создавайте его один раз: `useState(() => createXBackend())` или на уровне модуля. Бэкенд, созданный прямо в рендере, перемонтируется при каждой перерисовке.
- `theme`, `locale`, `ai`, `pageContext`, `fontFamily`, `fontSize`, `ariaLabel`, `screenReaderMode` и `onEvent` обновляются на лету; `welcome` применяется при монтировании.
- У ref-хэндла есть `run`, `insert`, `focus` и `clear`. `run()` отклоняется с `AbortError`, пока терминал не смонтирован.
- Последовательность StrictMode «смонтировать, размонтировать, смонтировать» оставляет ровно один рабочий терминал.
- Модуль начинается с `'use client'`. В Next.js App Router создавайте бэкенд в клиентском компоненте; см. [рецепт](./embedding.ru.md#nextjs-app-router).

## Элемент `<docs-terminal>`

```html
<docs-terminal theme="auto" locale="ru" style="height: 300px"></docs-terminal>
```

```ts
import '@xterm/xterm/css/xterm.css'
import { defineDocsTerminal } from 'docsterm/element'
import { createShellBackend } from 'docsterm/shell'

defineDocsTerminal()

const element = document.querySelector('docs-terminal')
if (element) {
  element.backend = createShellBackend({ cwd: '/project' })
  element.addEventListener('docsterm-error', (event) => {
    if (event.detail.phase === 'init') console.warn(event.detail.message)
  })
}
```

- `defineDocsTerminal(tagName = 'docs-terminal')` регистрирует элемент. Сам импорт модуля ничего не регистрирует, повторный вызов ничего не делает, а в Node функция не делает ничего вовсе, так что она безопасна при серверной сборке.
- Атрибуты: `backend` (`shell`, `javascript`, `pyodide` или `websocket`, загружается по требованию с настройками по умолчанию), `url` (обязателен для `websocket`), `locale`, `theme` (`light`, `dark`, `auto`), `font-size`, `font-family`, `aria-label` и `welcome` (читается при монтировании).
- Свойства: `backend` (любой `Backend`; важнее атрибута), `theme` (ещё и объект `TerminalTheme`; важнее атрибута), `ai`, `pageContext`, `onEvent` и только для чтения `terminal` (`DocsTerminal` или `null`). Методы: `run`, `insert`, `clear`, `focus`.
- События `docsterm-ready`, `docsterm-error` и `docsterm-event` — это `CustomEvent` с [событием](#управляющий-api) в `detail`; они всплывают и проходят сквозь теневые корни. `docsterm-error` приходит для ошибок любой фазы, так что сбои запуска отбирайте по `detail.phase === 'init'`. `addEventListener` типизирован для этих событий, а `document.querySelector('docs-terminal')` возвращает `DocsTerminalElement`.
- Элемент живёт в light DOM: подключите на странице `@xterm/xterm/css/xterm.css` и задайте элементу высоту. Он получает `display: block`, если ваш CSS не задал другое значение.

Полный справочник и рецепты для Vue, Astro/Starlight и обычного HTML — в [docs/embedding.ru.md](./embedding.ru.md#элемент-docs-terminal).

## Опции виджета

`new DocsTerminal(options)` и React-компонент принимают:

| Опция | Тип | По умолчанию | На лету |
| --- | --- | --- | --- |
| `backend` | `Backend` | обязательна | нет: создайте новый терминал (React и элемент перемонтируются сами) |
| `ai` | `AIProvider` | нет: строки с `#` уходят в бэкенд, `explain` недоступен | да |
| `locale` | `'en'` или `'ru'` | язык браузера (`ru*` — русский, остальное — английский) | да |
| `theme` | `'light'`, `'dark'`, `'auto'` или `TerminalTheme` | `'auto'` | да |
| `fontFamily` | строка | `monospace` | да |
| `fontSize` | число | `14` | да |
| `pageContext` | `Partial<PageContext>` | собирается со страницы | да |
| `welcome` | строка | локализованное приветствие | нет |
| `ariaLabel` | строка | `Terminal` / `Терминал` | да |
| `screenReaderMode` | логическое | `false` | да |
| `onEvent` | `(event) => void` | нет | да |

- `'auto'` следует за `prefers-color-scheme`, в том числе после монтирования. Тема-объект дополняется встроенной светлой или тёмной темой, которая выбирается по яркости её `background`. xterm поднимает контраст текста хотя бы до 4,5:1 с любой темой.
- Контекст страницы — это заголовок, URL, мета-описание и до 30 подзаголовков `h1`–`h3`; AI получает заголовок, описание и первые 15 подзаголовков. В одностраничных приложениях передавайте `pageContext`, если документ не описывает текущий маршрут.
- У элемента терминала `role="region"` и подпись; та же подпись достаётся полю ввода xterm.

## Свой бэкенд

```ts
import type { Backend, BackendRunResult, InteractiveRun, RunContext, RunOutcome } from 'docsterm'

const sleep = (ms: number) => new Promise((resolve) => setTimeout(resolve, ms))

function ticker(context: RunContext): InteractiveRun {
  let finish!: (result: BackendRunResult) => void
  const done = new Promise<BackendRunResult>((resolve) => {
    finish = resolve
  })
  let ticks = 0
  let stopped = false
  context.write('\x1b[?1049h')
  const timer = setInterval(() => {
    ticks += 1
    context.write(`\x1b[H\x1b[2Jtick ${ticks}, press q to quit`)
  }, 500)
  const stop = (exitCode: number) => {
    if (stopped) return
    stopped = true
    clearInterval(timer)
    context.write('\x1b[?1049l')
    finish({ output: `stopped after ${ticks} ticks`, exitCode })
  }
  return {
    done,
    onKey: (data) => {
      if (data === 'q') stop(0)
      if (data === '\x03') stop(130)
    },
    cancel: () => stop(130),
  }
}

export function createDemoBackend(): Backend {
  return {
    id: 'demo',
    prompt: 'demo> ',
    async init(host) {
      host.write('commands: build, ticker\n')
    },
    async run(command: string, context?: RunContext): Promise<RunOutcome> {
      const name = command.trim()
      if (name === 'ticker' && context) return ticker(context)
      if (name !== 'build') return { output: `${name}: unknown command`, exitCode: 127 }
      for (const step of ['compile', 'bundle', 'upload']) {
        if (context?.signal.aborted) return { output: '', exitCode: 130 }
        context?.write(`${step}...\n`)
        await sleep(300)
      }
      return { output: 'build complete', exitCode: 0 }
    },
    complete({ line, cursor }) {
      const word = line.slice(0, cursor)
      return { from: 0, to: cursor, candidates: ['build', 'ticker'].filter((name) => name.startsWith(word)) }
    },
    describe: () => 'A demo CLI. Commands: build (prints three steps), ticker (a full-screen ticker, q quits).',
    dispose() {},
  }
}
```

Контракт (`Backend` и связанные типы экспортируются из `docsterm`):

- **Жизненный цикл.** `init(host)` вызывается при монтировании. Отказ печатается как `окружение не запустилось: <сообщение>` с советом перезагрузить страницу, и `mount()` отклоняется. `dispose()` отменяет текущую работу и освобождает воркеры и сокеты, но объект должен остаться пригодным: `init()` после `dispose()` обязан работать — именно так поступают StrictMode в React и перемонтирование, — а двойной `init()` не должен ничего терять.
- **Вывод.** `context.write(text)` выводит потоком, пока команда работает. Возвращённый `output` содержит только то, что не ушло потоком, и печатается после потока; бэкенд без потока возвращает там всё. Если возвращённый вывод начинается с уже выведенного текста, эта копия отбрасывается. `context.write` действует, только пока `run()` не завершился, и никогда — после Ctrl+C или `dispose()`; поздний вывод идёт через `host.write()`, который печатает над приглашением.
- **Отмена.** `context.signal` срабатывает по Ctrl+C и при `dispose()`. Завершайтесь быстро, по соглашению с кодом 130.
- **Коды возврата.** `exitCode` должен быть конечным числом; числовая строка принимается, всё остальное считается 0. Ненулевой код делает команду той, о которой говорит `explain`. Для ограничения времени используйте 124.
- **Язык.** `context.locale` и `host.locale` (живое значение) сообщают язык читателя.
- **Приглашение.** `prompt` читается перед каждым приглашением, так что это может быть геттер, который следит за рабочим каталогом.
- **Продолжение строк.** `isComplete(source)` получает все набранные строки, соединённые `\n`. `false` запрашивает ещё строку с `continuationPrompt` (по умолчанию `'... '`); пустая строка тоже добавляется — так Python закрывает блок. Ctrl+C отбрасывает накопленные строки.
- **Описание.** `describe()` возвращает простой текст без управляющих последовательностей, не длиннее примерно 600 символов: что выполняется и какие команды или синтаксис есть. Его печатает `help` и получает AI.
- **Дополнение.** `complete({ line, cursor })` возвращает `{ from, to, candidates }` или `null`; указанный диапазон заменяется.

### Интерактивные программы

Вместо результата `run()` может вернуть `InteractiveRun`:

- Пока программа работает, `onKey(data)` получает каждое нажатие как сырые данные терминала. Вставка приходит в том виде, в каком её отправляет xterm: переводы строк становятся `\r`, а маркеры `\x1b[200~`…`\x1b[201~` вокруг текста появляются, только если программа включила bracketed paste (`\x1b[?2004h`). Возвращайте `done` — промис итогового результата.
- Первый Ctrl+C передаётся в `onKey` как `\x03`, и программа сама решает, что он значит, — обрабатывайте его. Второй Ctrl+C в течение секунды вызывает `cancel()` и бросает запуск, возвращая приглашение.
- `cancel()` вызывается и тогда, когда интерактивный запуск пришёл уже после того, как читатель нажал Ctrl+C. Запись внутри `cancel()` доходит до экрана, так что уходите с альтернативного экрана именно там; во время `dispose()` она отбрасывается, потому что терминал удаляется.
- `resize(columns, rows)` вызывается при изменении размера терминала.
- Вывод при включённом альтернативном экране (`\x1b[?1049h`, `?1047h`, `?47h`) никогда не попадает в `explain`, к AI и в `RunReport.output`; текст на обычном экране попадает.

## Content-Security-Policy

| Часть | Что нужно |
| --- | --- |
| Любая страница с терминалом | `style-src 'unsafe-inline'`: xterm.js 6 записывает тему и размеры ячеек в элементы `<style>`. Плюс источник, откуда отдаётся `xterm.css` |
| Кнопки запуска | ещё один внедрённый элемент `<style>`, если не `styles: false` |
| `docsterm/shell`, `docsterm/mock` | ничего сверх этого |
| `docsterm/javascript` | `worker-src blob:` и `script-src 'unsafe-eval'` (воркер вычисляет код, а `blob:`-воркер наследует политику страницы). Заблокированный воркер печатает `заблокировано политикой Content-Security-Policy страницы (нужно worker-src blob:; script-src 'unsafe-eval')`. Воркер со своего домена через `createWorker` подчиняется политике собственного ответа |
| `docsterm/pyodide` | `worker-src blob:` (или воркер со своего домена через `createWorker`), `script-src https://cdn.jsdelivr.net 'wasm-unsafe-eval'`, `connect-src https://cdn.jsdelivr.net`, а для `pip install` ещё `https://pypi.org https://files.pythonhosted.org`. Если задан `indexURL`, вместо CDN укажите свой источник |
| `docsterm/wasi` | `script-src 'wasm-unsafe-eval'`; `worker-src blob:` (без него команды завершаются с `заблокировано политикой Content-Security-Policy страницы (нужно worker-src blob:)`, см. [WASI](#docstermwasi)); `connect-src` для адреса `.wasm`, если он на другом источнике |
| `docsterm/websocket` | `connect-src` для сервера, например `wss://sandbox.example.com` |
| `docsterm/anthropic` | `connect-src https://api.anthropic.com` (или ваш прокси) |
| `docsterm/openai` | `connect-src` для адреса пресета или вашего `baseURL` (`http://localhost:11434`, `http://localhost:1234` для локальных моделей) |

Без директивы `worker-src` браузеры смотрят в `child-src`, а затем в `script-src`, так что `blob:` тогда нужно разрешить там. `'unsafe-eval'` разрешает и компиляцию WebAssembly.
