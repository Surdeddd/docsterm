# Эталонный WebSocket-сервер docsterm

[English version](README.md)

Сервер для бэкенда `websocket` в docsterm, который даёт каждому читателю настоящий терминал: один одноразовый Docker-контейнер и один псевдотерминал на подключение. Эхо, редактирование строки, Ctrl+C как SIGINT, запросы `read` и полноэкранные программы (`vi`, `top`, `less`) работают так же, как в локальном терминале, а `cd` и `export` сохраняются между командами.

Сервер говорит на протоколе WebSocket v2 и остаётся совместимым с клиентами v1.

> **Этот сервер выполняет команды, которые вводят посторонние люди.** Он никогда не запускает оболочку на хосте: контейнер стартует через node-pty с массивом аргументов, без сети, с корневой файловой системой только для чтения, без capabilities и с ограничениями на процессор, память и число процессов. Так и оставляйте. Не монтируйте в песочницу каталоги хоста и не ослабляйте флаги ниже, если не понимаете последствий.

## Быстрый старт

Нужны Node.js 22 или новее, Docker и образ с POSIX `sh`, `stty` и `dd` (подходят образы Alpine, BusyBox и Debian).

```sh
pnpm install            # из корня репозитория (пример — пакет рабочего пространства)
node examples/websocket-server/server.mjs
```

При запуске сервер печатает в stdout одну машиночитаемую строку, например:

```json
{"event":"listening","host":"127.0.0.1","port":8080,"url":"ws://127.0.0.1:8080"}
```

Журнал идёт в stderr. Подключение виджета:

```ts
import { createWebSocketBackend } from 'docsterm/websocket'

const backend = createWebSocketBackend({ url: 'ws://127.0.0.1:8080' })
```

Если образа нет локально, сервер один раз скачивает его при запуске. Дальше каждое подключение запускает контейнер с `--pull never`.

## Песочница

Для каждого подключения сервер создаёт контейнер и затем подключается к нему через node-pty:

```text
docker create --rm -i -t --pull never --network none --memory 256m --memory-swap 256m --cpus 0.5
  --pids-limit 128 --read-only --tmpfs /work:rw,exec,size=64m,uid=65534,gid=65534,mode=0700
  --tmpfs /tmp:rw,size=16m,uid=65534,gid=65534,mode=1777 -w /work --user 65534:65534
  --cap-drop ALL --security-opt no-new-privileges -e HOME=/work -e TERM=xterm-256color
  --label docsterm.sandbox=1 --label docsterm.owner=<host>/<server pid> --name docsterm-<random> <IMAGE> sh
docker start --attach --interactive --detach-keys ctrl-^,ctrl-_ <container id>
```

- Оболочка работает от непривилегированного пользователя 65534 (`nobody`), а не от root; изменить можно через `SANDBOX_USER`.
- `--memory-swap` равен `--memory`, поэтому песочница не может уходить в своп.
- `/work` — домашний каталог и единственное большое место для записи, он принадлежит пользователю песочницы. На нём разрешён `exec`, чтобы в учебных примерах работал `./script.sh`: по умолчанию Docker монтирует tmpfs с `noexec`.
- `/tmp` — маленький tmpfs для записи: многие утилиты его ожидают.
- `--detach-keys` уводит последовательность отсоединения Docker с Ctrl+P, которой пользуются `vi`, `less` и оболочки.
- Контейнер создаётся отдельным шагом, поэтому сервер всегда знает его id и может удалить его, даже если читатель отключился во время запуска. Контейнер удаляется (`docker rm -f`, который сначала его убивает; с несколькими повторами), когда читатель отключается, по истечении лимита простоя или длительности сессии, после `exit` (запускается новый) и когда сервер получает SIGINT или SIGTERM. Место подключения освобождается только после удаления контейнера, поэтому контейнеров никогда не больше, чем `MAX_CONNECTIONS`.
- При запуске и каждые пять минут сервер удаляет помеченные контейнеры, которые не работают и старше минуты, а также контейнеры, чей сервер на этой машине уже не работает (остались после SIGKILL). Убрать вручную: `docker ps -aq --filter label=docsterm.sandbox=1 | xargs docker rm -f`.
- При запуске сервер читает `docker info` и печатает `WARNING`, если демон запускает контейнеры без профиля seccomp. Для публичного развёртывания используйте усиленную среду: gVisor (`runsc` как среда по умолчанию в демоне) или переназначение пространства пользователей (`userns-remap`), и не выключайте профиль seccomp демона.

`SANDBOX=local` вместо Docker запускает обычный локальный `/bin/sh` в новом временном каталоге. Никакой изоляции у него нет, без `NODE_ENV=test` сервер отказывается так работать: режим существует только для интеграционного теста. Его каталоги называются `docsterm-sandbox-<pid сервера>-*` и удаляются в конце сессии; сервер, убитый через SIGKILL, этого сделать не может, поэтому каждый локальный сервер при запуске удаляет каталоги серверов, которые уже не работают (и каталоги без pid старше десяти минут). Кроме того, локальный сервер завершается, когда умирает запустивший его процесс.

## Протокол v2

Все кадры — текстовые кадры с JSON.

От клиента к серверу:

| сообщение | смысл |
| --- | --- |
| `{"type":"run","id":1,"command":"ls -l","columns":80,"rows":24,"locale":"ru"}` | выполнить команду; `columns` и `rows` необязательны и сначала меняют размер pty; `locale` необязателен и выбирает язык уведомлений сервера для этой команды (`ru` или `ru-*` — русский, всё остальное — английский) |
| `{"type":"stdin","id":1,"data":"y\r"}` | сырые нажатия клавиш для выполняющейся команды `id`, пишутся в pty без изменений |
| `{"type":"cancel","id":1}` | остановить команду `id` |
| `{"type":"resize","columns":120,"rows":40}` | изменить размер pty (в любой момент; один размер на подключение) |
| `{"type":"ping"}` | проверка связи |
| `{"type":"auth","token":"…"}` | первое сообщение, только если задан `TOKEN` и он не передан как `?token=` |

От сервера к клиенту:

| сообщение | смысл |
| --- | --- |
| `{"type":"ready","protocol":2,"features":["pty","resize","prompt","ping"],"prompt":"sandbox:~$ ","banner":"…"}` | сессия открыта; `prompt` и `banner` необязательны |
| `{"type":"output","id":1,"chunk":"…"}` | сырой вывод терминала для команды `id`, вместе с escape-последовательностями, концы строк `\r\n` |
| `{"type":"exit","id":1,"code":0,"prompt":"sandbox:~/app$ "}` | команда `id` завершилась; `prompt` отражает новый рабочий каталог |
| `{"type":"pong"}` | ответ на `ping` |

Возможности (`features`):

- `pty`: команда выполняется на настоящем pty. Пока она идёт, клиент пересылает каждую клавишу как `stdin` (включая Ctrl+C); удалённая дисциплина линии делает эхо, редактирует строку и превращает `\x03` в SIGINT.
- `resize`: сообщения `resize` и поля `columns`/`rows` в `run` доходят до pty (`stty size`, полноэкранные программы).
- `prompt`: `ready` (если песочница уже поднялась) и каждый `exit` несут приглашение.
- `ping`: на `ping` сервер отвечает `pong`.

Идентификаторы — неотрицательные целые числа, их выбирает клиент. Клиент v1 (без `columns`, `rows`, `stdin`, `resize`, `ping`) продолжает работать без изменений.

### Когда приходит `ready`

`ready` отправляется сразу после того, как подключение принято (после проверки origin и токена), и не ждёт медленного старта контейнера: сервер ждёт песочницу не дольше `READY_WAIT_MS` (по умолчанию 500 мс). Если оболочка к этому моменту готова, `ready` несёт приглашение; если нет, приглашения в нём нет, и его принесёт первый `exit`. Команда `run`, пришедшая раньше, чем оболочка готова, ждёт её (не дольше `START_TIMEOUT_MS`). Если песочница не смогла запуститься, на эту команду приходит строка `docsterm-server: не удалось запустить песочницу` (или её английский вариант) и код выхода 125, а подключение закрывается с кодом 1011.

### Приглашение

`sandbox:<dir>$` и один пробел, где `<dir>` — рабочий каталог, в котором домашний каталог (`/work`) показан как `~`. От путей длиннее 40 символов остаются два последних компонента (`sandbox:…/some/thing$`). Управляющие символы и символы управления направлением текста заменяются на `?`.

### Коды выхода и уведомления

Уведомления сервера пишутся в вывод команды одной строкой, которая начинается с `docsterm-server:`, на английском или русском в зависимости от `locale` команды (если поля нет — на английском). Ниже приведены русские тексты. Причины закрытия соединения остаются на английском.

| код | когда |
| --- | --- |
| собственный код команды | обычное завершение |
| 1 | второй `run`, пока выполняется другая команда (`другая команда ещё выполняется`) |
| 2 | команда отклонена: не строка, длиннее `MAX_COMMAND_LENGTH` или содержит управляющие символы, кроме табуляции и перевода строки |
| 124 | команда не получала ввода от читателя в течение `COMMAND_TIMEOUT_MS` (`команда остановлена: … без ввода`) |
| 125 | песочница не смогла запуститься |
| 130 | отменена через `cancel` |
| N | `exit N`: оболочка завершилась; сервер запускает новую песочницу, сообщает об этом (`оболочка завершилась с кодом N; запущена новая песочница`) и возвращает N. Файлы, переменные и рабочий каталог сбрасываются. |

Подробности поведения:

- **Одна команда за раз.** `run`, пришедший, пока предыдущая команда отменяется (после `cancel` или тайм-аута), ставится в очередь и стартует, как только предыдущая завершится; `stdin` для команды в очереди доставляется после её старта. На любой другой одновременный `run` приходит код 1. `run` с идентификатором выполняющейся или ожидающей команды игнорируется.
- **Отмена.** `cancel` пишет в pty Ctrl+C. Если через `CANCEL_GRACE_MS` (2 с) команда не завершилась, сервер убивает группу процессов переднего плана внутри песочницы; если и после второго такого интервала оболочка не вернулась, песочница заменяется новой, о чём говорит уведомление. Код выхода во всех случаях 130. Ctrl+C, присланный как `stdin`, — просто нажатие клавиши: решает программа (команда оболочки обычно завершается с кодом 130).
- **Тайм-аут.** `COMMAND_TIMEOUT_MS` (120 с) отсчитывается от старта команды и начинается заново с каждым принятым сообщением `stdin`, поэтому читателя, который работает в `vi` или отвечает на `read`, сервер никогда не обрывает, а оставленная без присмотра зациклившаяся команда всё равно завершится с кодом 124 по истечении лимита. Вывод таймер не сбрасывает, как и сообщения `stdin`, отброшенные ограничением скорости.
- **Лимит вывода.** После `OUTPUT_LIMIT_BYTES` (5 МБ) вывода сервер пишет уведомление, отбрасывает остальное и прерывает команду (обычно она завершается с кодом 130). Лимит считается по размеру в JSON, который уходит по сети, поэтому вывод с большим числом управляющих байтов достигает его раньше.
- **Управление потоком.** Когда медленного клиента ждёт больше 1 МиБ вывода, сервер перестаёт читать pty, и программа блокируется на собственном выводе; чтение возобновляется, когда очередь падает ниже 256 КиБ. Клиент, который ничего не читает дольше `STALL_TIMEOUT_MS` (30 с) или накопил больше 8 МиБ, отключается.
- **Скорость сообщений.** Каждое подключение может разом отправить `MESSAGE_BURST` (200) сообщений и дальше `MESSAGES_PER_SECOND` (100) в секунду; лишние сообщения отбрасываются. Сообщения `stdin` длиннее 16 символов (вставка текста) расходуют ещё и бюджет байтов `STDIN_BURST_BYTES` (256 КБ), который пополняется со скоростью `STDIN_BYTES_PER_SECOND` (64 КБ/с); отдельные нажатия клавиш проходят всегда. `pong` отправляется не чаще раза в 500 мс, а серия сообщений `resize` применяется один раз, с последним размером (ожидающий resize применяется перед следующим `stdin` или `run`).
- **Длительность сессии.** Подключение живёт не дольше `MAX_SESSION_MS` (30 мин). Затем выполняющаяся команда, если она есть, получает уведомление (`достигнут лимит длительности сессии (30 мин)`), и подключение закрывается с кодом 1000 `session limit reached`.
- **Фоновые задания.** Вывод, появившийся после завершения команды (например, от `sleep 1 && echo late &`), отбрасывается.
- **Ввод наперёд.** Клавиши, которые команда не прочитала до своего завершения, отбрасываются, поэтому они никогда не выполнятся как случайные команды.

### Ошибки и ограничения

| ситуация | результат |
| --- | --- |
| обычный HTTP-запрос | `426 Upgrade Required` |
| `Origin` не разрешён | HTTP 403 до рукопожатия WebSocket |
| неверный `?token=` | HTTP 401 |
| больше `MAX_CONNECTIONS_PER_IP` подключений с одного адреса или больше `CONNECTS_PER_MINUTE_PER_IP` попыток подключения в минуту | HTTP 429 |
| больше `MAX_CONNECTIONS` подключений или сервер останавливается | HTTP 503 |
| некорректный JSON, двоичные кадры, неизвестные типы, неверные поля, кадры больше `MAX_MESSAGE_BYTES` | игнорируются; сессия продолжает работать |
| кадры больше `max(4 × MAX_MESSAGE_BYTES, 1 МиБ)` | закрытие на уровне WebSocket (1009) |
| нет сообщения `auth` или оно неверное, когда нужен токен | закрытие 1008 `unauthorized` (`authentication timed out` по истечении `AUTH_TIMEOUT_MS`) |
| нет активности в течение `IDLE_TIMEOUT_MS` | закрытие 1000 `idle limit reached`, песочница уничтожается |
| сессия старше `MAX_SESSION_MS` | закрытие 1000 `session limit reached`, песочница уничтожается |
| клиент перестал читать (см. «Управление потоком») | соединение обрывается без кадра закрытия |
| песочница не запускается или завершилась между командами | закрытие 1011 |
| остановка сервера | закрытие 1001 |

## Безопасность

- **Origin.** Браузер добавляет заголовок `Origin` к каждому рукопожатию WebSocket, поэтому список разрешённых origin не даёт чужим страницам пользоваться вашим сервером. Без `ALLOWED_ORIGINS` принимаются только страницы с локального адреса (`http://localhost`, `http://127.0.0.1`, `http://[::1]` на любом порту, а также `https`); страница с другого сайта подключиться не может. В продакшене задайте в `ALLOWED_ORIGINS` список точных origin через запятую (`https://docs.example.com,https://example.github.io`); `*` разрешает любой origin и не рекомендуется. Запросы без заголовка `Origin` (клиенты не из браузера) разрешены: для них используйте `TOKEN`.
- **Токен.** Если задан `TOKEN`, клиент должен предъявить его в адресе как `?token=` или первым сообщением `{"type":"auth","token":"…"}`. Сравнение выполняется за постоянное время. Токен на публичной странице документации виден каждому читателю: он ограничивает случайное использование, но секретом не является.
- **Лимиты.** Число подключений и попыток подключения ограничено для каждого клиента и в целом. Клиенты группируются по адресу IPv4 и по сети IPv6 /64 (адреса IPv4, отображённые в IPv6, считаются как IPv4). За обратным прокси все читатели приходят с адреса прокси, поэтому увеличьте `MAX_CONNECTIONS_PER_IP` и `CONNECTS_PER_MINUTE_PER_IP` или ограничивайте подключения в самом прокси. Отказы попадают в журнал не чаще десяти раз за десять секунд, после чего пишется число пропущенных строк.
- **Подделка границ.** Оболочка хранит nonce подключения в `__dt_n`, поэтому читатель, который намеренно печатает поддельную метку (или переопределяет `__dt_*`), может завершить или запутать только свою команду и свою сессию; у других подключений другие nonce и другие песочницы.
- **Журнал** содержит номера подключений, адреса клиентов, причины завершения и коды закрытия. В нём никогда не бывает команд, нажатий клавиш, вывода, адресов запросов и токенов.
- **Адрес.** По умолчанию сервер слушает `127.0.0.1`. Прежде чем открывать его наружу, поставьте перед ним прокси с TLS (`wss://`).

## Настройка

| переменная | по умолчанию | смысл |
| --- | --- | --- |
| `PORT` | `8080` | порт; `0` выбирает свободный (см. строку `listening`) |
| `HOST` | `127.0.0.1` | адрес для прослушивания |
| `IMAGE` | `alpine:3` | образ песочницы; в продакшене закрепите digest |
| `ALLOWED_ORIGINS` | только локальные | точные origin через запятую или `*` |
| `TOKEN` | нет | общий токен, см. «Безопасность» |
| `BANNER` | нет | текст, который отправляется с `ready` (не больше 500 символов) |
| `READY_WAIT_MS` | `500` | сколько `ready` может ждать песочницу (от 0 до 1000) |
| `START_TIMEOUT_MS` | `30000` | лимит на запуск песочницы |
| `COMMAND_TIMEOUT_MS` | `120000` | лимит на команду без ввода от читателя |
| `CANCEL_GRACE_MS` | `2000` | ожидание после Ctrl+C перед уничтожением задания переднего плана |
| `OUTPUT_LIMIT_BYTES` | `5242880` | лимит вывода на команду |
| `IDLE_TIMEOUT_MS` | `600000` | лимит простоя подключения |
| `AUTH_TIMEOUT_MS` | `10000` | время на сообщение `auth` |
| `MAX_MESSAGE_BYTES` | `65536` | кадры больше игнорируются |
| `MAX_COMMAND_LENGTH` | `16384` | символов в команде |
| `MAX_STDIN_LENGTH` | `32768` | символов в одном сообщении `stdin` |
| `MAX_CONNECTIONS` | `20` | подключений всего |
| `MAX_CONNECTIONS_PER_IP` | `4` | подключений с одного адреса (IPv6: с одной сети /64) |
| `CONNECTS_PER_MINUTE_PER_IP` | `30` | попыток подключения с одного адреса в минуту |
| `MAX_SESSION_MS` | `1800000` | предельная длительность сессии |
| `STALL_TIMEOUT_MS` | `30000` | сколько клиент может не читать вывод |
| `MESSAGE_BURST` | `200` | сообщений, которые подключение может отправить разом |
| `MESSAGES_PER_SECOND` | `100` | постоянная скорость сообщений на подключение |
| `STDIN_BURST_BYTES` | `262144` | бюджет байтов для длинных сообщений `stdin` |
| `STDIN_BYTES_PER_SECOND` | `65536` | скорость пополнения этого бюджета |
| `SANDBOX_USER` | `65534:65534` | `uid:gid` оболочки в песочнице |
| `SANDBOX_MEMORY` | `256m` | `--memory` и `--memory-swap` |
| `SANDBOX_CPUS` | `0.5` | `--cpus` |
| `SANDBOX_PIDS_LIMIT` | `128` | `--pids-limit` |
| `SANDBOX_WORK_SIZE` | `64m` | размер `/work` |
| `SANDBOX_TMP_SIZE` | `16m` | размер `/tmp` |
| `SANDBOX` | `docker` | `local` только с `NODE_ENV=test` |
| `LOCAL_SHELL` | `/bin/sh` | оболочка локальной тестовой песочницы |
| `LOCAL_START_DELAY_MS` | `0` | только для тестов: задерживает запуск локальной песочницы |

## Как устроены границы команд

Пока команд нет, оболочка работает с выключенным эхо и невидимым приглашением. Команда отправляется одной логической строкой `stty echo; eval '<команда>'; __dt_end $? <n>`, где сама команда взята в одинарные кавычки и разбита на короткие строки продолжения, поэтому оболочка прочитывает её целиком до того, как что-либо начнёт выполняться: команда, читающая stdin (`read x`, `cat`), получает нажатия клавиш читателя и никогда — служебную часть строки. Многострочные команды, here-документы и `# комментарии` в конце работают, потому что остаются внутри `eval`. `__dt_end` отбрасывает непрочитанный ввод наперёд, выключает эхо, восстанавливает обычные режимы терминала и печатает метку со случайным для каждого подключения nonce, кодом выхода и `$PWD`; сервер вырезает её из потока, в том числе когда она разбита между фрагментами, не добавляя и не удаляя ни одного байта вывода самой команды. Приглашение (`PS1`) — вторая метка с nonce: если оболочка вернулась к приглашению без метки завершения (dash и BusyBox обрывают всю строку при SIGINT или синтаксической ошибке), сервер ещё раз просит оболочку напечатать метку. Обе метки собираются только в момент печати из трёх переменных (`PS1='${__dt_a}${__dt_n}P${__dt_n}${__dt_b}'`, где в `__dt_a` и `__dt_b` лежат байты-разделители), поэтому ни одна переменная, тело функции, вывод `set`, `env` или `declare -p` не содержит метку целиком, и `echo "$PS1"` или `set` не могут сбить сервер с толку.

## Разработка

```sh
npx vitest run packages/docsterm/test/websocket-server.test.ts
```

Тест запускает сервер с `SANDBOX=local NODE_ENV=test PORT=0`. Чтобы проверить другую оболочку, задайте `LOCAL_SHELL=/bin/dash`.

node-pty 1.1.0 может установить свой `spawn-helper` без права на исполнение (`posix_spawnp failed`); сервер исправляет права при запуске.

## Известные ограничения

- Ctrl+C, пришедший ровно в момент между встроенной командой оболочки и стартом следующей программы (`printf x; sleep 10`), достаётся оболочке, а не программе, и оболочка ждёт эту программу — как в любом терминале. Читатель нажимает Ctrl+C ещё раз, или клиент отправляет `cancel`.
- На macOS pty на границах внутренних буферов может выдавать `\r\r\n` вместо `\r\n`; терминалы отображают оба варианта одинаково.
- В Docker Desktop демон часто работает без seccomp; сервер предупреждает об этом, но исправить не может.
- `set -x` заставляет оболочку выводить трассировку служебного вызова `__dt_end`. Переопределение или удаление `__dt_end`, `__dt_n`, `__dt_a` или `__dt_b`, а также намеренная печать `"$__dt_a$__dt_n"` ломают границы команд; такая сессия закончится тайм-аутом или новой песочницей.
