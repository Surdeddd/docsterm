# Changelog

All notable changes to `docsterm` are listed here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [semantic versioning](https://semver.org/) (before 1.0, a minor version may break the API). Each release lists breaking changes first.

## 0.8.0 - 2026-10-13

A hardening release: the defects found in the October 2026 audit are fixed or documented as known limits, the widget gains a control API, Run buttons and a custom element, the WebSocket backend speaks a second protocol version with a real pseudo-terminal, and a reference server replaces the README sample.

### Breaking

- **`#` asks the AI only for typed lines.** A line goes to the AI only when its first non-blank character was typed by the reader (a line recalled from history counts as typed). Lines from a paste, `run()`, `insert()` or a Run button go to the backend unchanged; in the JavaScript backend such a line is a syntax error. Without an `ai` provider every `#` line goes to the backend, where 0.7 printed "AI is not configured". `explain` likewise asks the AI only when typed; from a paste, `run()` or a Run button it goes to the backend.
- **`createWebSocketBackend()` returns `Backend` instead of `SimpleBackend`.** With a v2 server that has the `pty` feature and a `RunContext`, `run()` resolves to an `InteractiveRun`; code that calls `backend.run()` itself must check `isInteractiveRun()`.
- **WebSocket behaviour.** `init()` resolves on the server's `ready` message (or `readyTimeoutMs`, 1.5 s, after the socket opens) instead of on open. `run()` before `init()` or after a failed reconnect rejects with `not connected to the server` instead of resolving `{ output: 'not connected', exitCode: 1 }`. A socket that cannot be created rejects `init()` with `cannot connect to <url>`, with the browser's error as `cause`. `timeoutMs` became an inactivity limit (output restarts it) that ends the command with exit 124 instead of 1, and applies to protocol v1 only.
- **Custom JavaScript workers must speak the 0.8 protocol.** The host posts `{ type: 'init', globals, baseURL }` and `{ type: 'run', id, code, declarations, columns, outputLimit }`; the worker answers `{ type: 'ready', evalBlocked }`, `{ type: 'log', id, text }` and `{ type: 'result', id, value?, error? }` (types `HostMessage` and `WorkerMessage`). A 0.7 worker never reports ready, and `init()` fails after `initTimeoutMs`. The `persistTopLevelDeclarations` export is removed. A time-out now exits 124 (was 1).
- **`WorkerLike` is one shared, DOM-free type**, exported from `docsterm`, `docsterm/javascript`, `docsterm/pyodide` (as `PyodideWorker`) and `docsterm/wasi`. Its handlers are method signatures, `onmessage(event: { data: unknown })` and `onerror(event: unknown)`, so a DOM `Worker` is assignable without a cast; implementations typed with other handler parameters may need adjusting.
- **Anthropic client types.** `AnthropicLike` is `{ messages: AnthropicMessagesLike; beta?: { messages: AnthropicMessagesLike } }`. `create()` and `stream()` take an `AnthropicRequest` and `{ signal }` and return an `AnthropicMessage` or an `AnthropicTextStream` (new exported types, with `AnthropicRequestOptions` and `AnthropicEffort`). A `clientFactory` typed against 0.7's `Record<string, unknown>` parameters needs updating; a real `new Anthropic(…)` fits without a cast, and the factory may return a promise. `clientFactory` receives `undefined` when no key is configured and must then send no credentials. `KeyMissingError` now extends `AIProviderError` (code `key-missing`).
- **The `pyodide` peer dependency is removed.** Python runs in a module Web Worker that loads Pyodide from `indexURL` (default `https://cdn.jsdelivr.net/pyodide/v314.0.7/full/`); the `pyodide` npm package is no longer imported, so you can uninstall it and drop Vite's `optimizeDeps.exclude: ['pyodide']`. `PYODIDE_VERSION` is now `'314.0.7'`, an alias of the new `DEFAULT_PYODIDE_VERSION`; a self-hosted `indexURL` must serve that version.
- **Shell `>&word`.** `>&name` and `1>&name`, where `name` is not a number or `-`, send stdout and stderr to the file `name`, as in bash; 0.7 wrote stdout to a file literally named `&name`. `n>&name` with any other `n` prints `name: ambiguous redirect`.
- **WASI command lines.** Pipes, redirects, `&&`, `;`, variables, backticks, parentheses and a second command are refused with exit 2, and an unmatched quote is an error (0.7 passed them to the program as arguments). `splitCommandLine()` throws `CommandLineError`. Removed exports: `createWasiImports`, `buildWasiResult`, `WasiHostState`, `ExitSignal` and `encodeStringList`; use `createWasiHost` instead. Programs run in a Web Worker, with no silent fallback to running programs on the page: when the worker cannot start (CSP, no `Worker` global, a failing custom worker, or no ready within `initTimeoutMs`), `init()` rejects or runs fail with a localized message. Programs run on the page only with `worker: false` (or `instantiate`), which blocks the page and cannot stop compute loops.
- **OpenAI-compatible keys are bound to the endpoint (action needed).** The shared 0.7 key slot `docsterm:openai-key` is no longer read, because it could hold another vendor's key. Readers re-enter their OpenAI key once; it is stored per endpoint in `docsterm:key:openai`. Other endpoints use `docsterm:key:<preset>` or `docsterm:key:<host[:port]>` for a custom `baseURL`, and `defaultKeyName()` returns the slot. `OPENAI_KEY_NAME` is still exported but unused.
- **AI parsing errors.** `parseSuggestionText()` throws `AIProviderError('invalid')` instead of `SyntaxError`/`TypeError`, and `extractStreamDeltas()` throws `AIProviderError` on error payloads.
- **React.** `DocsTerminal` from `docsterm/react` is a `forwardRef` component (`ForwardRefExoticComponent<DocsTerminalProps & RefAttributes<DocsTerminalHandle>>`) instead of a plain function returning `JSX.Element`.

### Added

- **Control API** on `DocsTerminal`: `run(text)` returning `RunReport { exitCode, output }`, `insert(text)`, `focus()`, `clear()`, the `element` getter, `setOptions(patch)` for every live option, `setOnEvent()`, and the `onEvent` option with `DocsTerminalEvent` (`ready`, `command`, `interrupt`, `ai-suggest`, `ai-explain`, `error`). `run()` sets the reader's half-typed line and unfinished multi-line command aside and restores them afterwards; text that leaves a command unfinished gets one empty line, and if it is still unfinished nothing runs (exit 2 and an `error` event). New types `InputSource`, `CommandSource`, `RunReport`, `DocsTerminalEvent`, `DocsTerminalLiveOptions`; for custom widgets `SessionController.takeContinuation()`/`resumeContinuation()`, `SessionContinuation` and `SessionIO.printProse()`.
- **Run buttons:** `attachRunButtons(root, terminal, { selector, styles, locale, prompts })` adds a localized run button to code blocks and returns a cleanup function. Console lines starting with a prompt (default `'$ '` and `'% '`) run without it, continued after a trailing `\` or on lines starting with `>` and a space; `<br>` and the line elements of Docusaurus, Expressive Code and Shiki end lines; text hidden from the reader is skipped; a block without a command gets no button; the buttons of one `<pre>` share a `span.docsterm-run-bar`.
- **`docsterm/element`:** `defineDocsTerminal(tagName?)` registers a `<docs-terminal>` custom element with `backend`, `url`, `locale`, `theme`, `font-size`, `font-family`, `aria-label` and `welcome` attributes, `backend`/`theme` (a `TerminalTheme` object too)/`ai`/`pageContext`/`onEvent` properties, `run`/`insert`/`clear`/`focus` methods and bubbling `docsterm-ready`, `docsterm-error` and `docsterm-event` events. Types `DocsTerminalElement` (with typed `addEventListener`/`removeEventListener`), `DocsTerminalElementEventMap`, `BuiltInBackend`, and `HTMLElementTagNameMap['docs-terminal']`.
- **React:** a ref handle `DocsTerminalHandle { run, insert, focus, clear }`; `onReady(terminal)` and `onError(error)`; container attributes `id`, `title`, `role`, `aria-*` and `data-*`; every option except `backend` and `welcome` updates live; `'use client'` for the Next.js App Router.
- **WebSocket protocol v2** (backward compatible): `ready` announces `protocol: 2`, `features` (`pty`, `resize`, `prompt`, `ping`) and a prompt; `stdin`, `resize`, `ping`/`pong` messages; `exit` may carry the prompt; a heartbeat with automatic reconnects and localized notices. A command typed while an automatic reconnect is still waiting for `ready` waits for it (or `readyTimeoutMs`) before choosing the v1 or v2 path. `run` messages carry an optional `locale` (`en`/`ru`) so servers can localize their own notices; servers that do not know the field ignore it. New options `token`, `description`, `readyTimeoutMs`, `connectTimeoutMs`; new type `ClientMessage`.
- **WebSocket multi-line input:** typed or Run-button multi-line shell input runs as one command. The backend has a conservative POSIX `isComplete` (quotes, `$( )`, backticks, here-documents, `if`/`case`/loops, `{ }`, `( )`, trailing `\`, `|`, `&&`, `||`) and the continuation prompt `'> '`.
- **Reference server** in `examples/websocket-server/` (English and Russian READMEs): one disposable Docker container and pseudo-terminal per connection, protocol v1 and v2.
  - Sandbox: started with `docker create` and `docker start --attach --interactive`, as user 65534 (non-root) with `/work` and `/tmp` tmpfs owned by it, no swap (`--memory-swap` equals `--memory`), no network, a read-only root, all capabilities dropped, `no-new-privileges`, 128 processes, 0.5 CPU and 256 MiB. The server warns at start-up when Docker runs containers without a seccomp profile (Docker Desktop on macOS does) and recommends gVisor (`runsc`) or userns-remap for public deployments.
  - Limits, all configurable: the pty pauses above 1 MiB of unsent output and resumes below 256 KiB; a client that reads nothing for 30 s or lets 8 MiB pile up is dropped; long `stdin` messages draw from a 256 KB budget refilled at 64 KB/s (keystrokes always pass); 200 messages in a burst and 100 per second per connection; at most one `pong` per 500 ms; coalesced resizes; 30 connections per minute per client (IPv4 address or IPv6 /64); sessions end after 30 minutes with a notice and close code 1000.
  - Notices are localized by the `locale` of each `run` and start with `docsterm-server:`. Slots are released only after a container is gone, and leftover labelled containers are swept at start-up and every 5 minutes. The command boundary marker is assembled only at prompt time, so printing `PS1`, `set` or `env` does not break a session; forging a boundary breaks only the reader's own session.
- **Widget:** the `history` builtin; `help` prints the keys and the backend's description; `ariaLabel` and `screenReaderMode` options; `setTheme`, `setLocale`, `setAI` and `setPageContext` work before and after mount; `theme: 'auto'` follows the system live; object themes fill the gaps from a built-in theme; word movement with Alt/Ctrl+arrows, Ctrl+B/F/D/T/Y/L, Alt+D, Ctrl+Delete, Ctrl+Backspace and Alt+Backspace; Shift+Tab or Esc then Tab leaves the terminal; Ctrl+Shift+C/V; bracketed paste that runs pasted lines one by one; type-ahead while a command runs; Unicode 11 character widths; multi-line commands with continuation prompts.
- **Backend contract:** `continuationPrompt`, `isComplete()`, `describe()`, `InteractiveRun.resize()` and `cancel()`, `RunContext.locale`, `BackendHost.locale`.
- **Root exports:** `AIProviderError`, `isAbortError`, `AIErrorCode`, `formatMessage`, `stripAnsi`, `sanitizeCommand`, `sanitizeProse`, `displayWidth` and related width helpers, `WorkerLike`, `LineSnapshot`.
- **Shell:** expansion inside double quotes, `${VAR:-x}` and the other parameter forms, `${#VAR}`, pattern removal, `$?`, `$(…)` and backticks, brace expansion, `~`, `#` comments, file-descriptor redirects (`2>`, `2>&1`, `>&2`, `&>`, `>|`, `n>&-`), `/dev/null`, `!`, `NAME=value command`, newline-separated commands, continuation lines, `[abc]` and POSIX classes in globs; builtins `printf`, `tee`, `basename`, `dirname`, `type` and `unset`; `less`/`more` on the alternate screen with more keys; Tab completion that understands quotes, escapes names and offers only directories after `cd`; custom commands may return an `InteractiveRun`.
- **JavaScript:** a real parser (acorn) so declarations persist with top-level `await`, Node-like value formatting, completion values, more `console` methods and format specifiers, relative URLs in `fetch` and friends, continuation lines, options `initTimeoutMs`, `outputLimit` and `baseURL`.
- **Python:** runs in a Web Worker; continuation lines; `pip install`; automatic loading of imported Pyodide packages; options `packages` and `createWorker`; exports `DEFAULT_PYODIDE_VERSION` and `PYODIDE_WORKER_SOURCE`; Ctrl+C raises `KeyboardInterrupt` in place where possible; `exit()`/`sys.exit(n)` set the exit status.
- **WASI:** programs run in a Web Worker so Ctrl+C and time limits stop them; options `timeoutMs`, `initTimeoutMs`, `outputLimit`, `usage`, `worker` and `createWorker`; every unknown WASI call returns `ENOSYS` so more programs start; clock and sleep support; `#` comments and continuation lines; exports `createWasiHost`, `isCompleteCommandLine`, `CommandLineError`, `WASI_WORKER_SOURCE`.
- **OpenAI-compatible provider:** options `tokenParam` and `jsonMode` with per-preset defaults, `defaultKeyName()`, one retry without `response_format` when a server rejects it. A custom `baseURL` that is not a hosted vendor endpoint no longer needs an API key; without one no `Authorization` header is sent.
- **Anthropic provider:** options `effort` and `fallbacks` with per-model defaults; one retry without a field the API rejects, remembered until reload. New `baseURL` option. With `baseURL` or a custom `clientFactory` no key is required, and a keyless request sends neither `x-api-key` nor `Authorization`.
- **Mock AI provider:** a `locale` option, and requests can be cancelled.
- **Widget messages** (welcome, help, errors, AI notes) wrap at word boundaries to the terminal width.
- **Docs:** `CHANGELOG.md`, a Russian embedding guide, recipes for Next.js, Docusaurus, Vue/VitePress, Astro/Starlight and plain HTML, and a "Security and limits" section in the README.

### Changed

- **Anthropic defaults:** model `claude-opus-5-5` (was `claude-opus-5`), `maxTokens` 8192 (was 1024), `effort: 'low'` for models that support it, server-side fallbacks for Fable 5.1, Mythos, Opus 5.x and Sonnet 5.5; the SDK loads on the first request instead of at import.
- **OpenAI-compatible defaults:** `maxTokens` 4096 (was 1024); `jsonMode` is `schema` for `openai` and `lmstudio` and `object` elsewhere (always `object` before); `max_completion_tokens` for `openai` and `groq`.
- **AI flow:** the y/N question is the prompt, the explanation is printed above the command, and a suggestion too tall for the screen is refused. Anything typed before the question appears is discarded. Errors are localized; server errors read `AI request failed: <status>: <message>`.
- **Time limits** end with exit code 124 in the JavaScript, WASI and WebSocket backends.
- **Widget:** the welcome line without AI no longer mentions `#`; `mount()` on a mounted instance throws synchronously; `dispose()` disposes the backend only if it was started; xterm's input element is labelled `Terminal`/`Терминал`; text contrast is raised to at least 4.5:1.
- **Shell:** `ls` prints one name per line and no colours when its output is piped or redirected; `ls missing` exits 1; unknown options exit 2; names sort with ICU collation; `history` is a widget builtin, not a shell command.
- **Package:** `@xterm/xterm` `^6.0.0` and `@xterm/addon-fit` `^0.11.0` are ranges instead of exact versions; new dependencies `@xterm/addon-unicode11` and `acorn` (loaded on demand); `typesVersions` makes the subpath types resolve under `node10`; the npm README is generated from the repository README with absolute links.
- **Peer dependency:** the `@anthropic-ai/sdk` range is now `>=0.50.1` (was `>=0.60.0`; verified with 0.50.1, 0.54.0, 0.60.0 and 0.131.0).
- **Development:** a CI workflow, `pnpm lint` (oxlint), `pnpm coverage`, `pnpm probe` (packs the library into clean projects) and `pnpm test:scripts`; `pnpm build` compiles into `.dist-next` and replaces `dist` only on success; `pnpm e2e` builds the library and the demo itself; the demo accepts `?isolated` for cross-origin isolation and has a React check page; the repository needs Node.js 22.22.2+, 24.15+ or 26 and pnpm 11.22.

### Fixed

- **Widget:** Alt/Ctrl+arrow word jumps did nothing in xterm 6; wide characters and emoji broke cursor placement; wrapped and multi-line prompts, very long lines and resizes corrupted the screen; a partial output line could be erased by the prompt; `^C` landed at the wrong place; typing during start-up was glued to the banner; React StrictMode left two terminals and a Python backend that never started; a `dispose()` during start-up could still initialise the backend and never dispose it; `theme: 'auto'` ignored later system changes; a failed start left "loading environment..." forever; web fonts loading late left a wrong column count; container padding made the terminal overflow; `history` printed nothing.
- **Session:** output streamed by a backend was lost or printed twice; Ctrl+C at the y/N question garbled the line and swallowed the next command; the y/N answer went into the history while the executed suggestion did not; a confirmed `help` bypassed the builtins; a missing API key printed a raw English error; `explain` got only the start of long outputs; backend exceptions were not recorded, so `explain` could not explain them.
- **Shell:** `"$VAR"` printed literally; `2>/dev/null`, `>&2` and `2>&1` created junk files; `cp`/`mv` with several sources and `mv x .` misbehaved; `ls` ignored extra operands; colour codes leaked into pipes and files; `which` found every name; `rm -rf /` deleted the root and broke the shell until reload; names such as `constructor` resolved to JavaScript internals; some glob and `${X%%pattern}` inputs froze the page.
- **JavaScript:** `console.log('a', 3)` printed a stray count; variables declared next to top-level `await` were lost; Ctrl+C left the runaway loop running so the next command timed out; relative URLs failed in the worker; values such as `NaN`, `Map` and regular expressions were mangled.
- **Python:** the runtime failed to start with the `pyodide` version npm installed; webpack (Docusaurus, Next.js) could not bundle the backend; `pip install` was a syntax error and bundled packages could not be imported; `True` printed as `true`; blocks could not span lines; output arrived only at the end; the backend could not start again after `dispose()`.
- **WASI:** Go programs and Rust programs using `std::fs` or `thread::sleep` failed to link or panicked; stdin bytes and stdout/stderr order were wrong; the module was recompiled for every command; the backend could not start again after `dispose()`; a looping program froze the page.
- **WebSocket:** output arrived only when the command finished; Ctrl+C sent nothing, and an abandoned command's timer killed the next one; the server banner appeared after the prompt; an unreachable server left the terminal on "loading environment..." with no error.
- **Mock:** a scripted entry with `delayMs` ignored Ctrl+C and kept the terminal busy until the delay ended; it now stops at once with exit 130.
- **AI providers:** the OpenAI preset sent `max_tokens`, which current OpenAI models reject; the `lmstudio` preset sent a JSON mode LM Studio rejects; SSE errors and non-SSE replies were swallowed, so `explain` showed an empty or cut-off answer as a success; an Anthropic answer cut at the token limit went unnoticed; cancelling did not stop the request.
- **Docs:** README samples that did not compile; the install section without peers; incomplete CSP guidance; React recipes that remounted on every render; the "plain-HTML recipe" link pointed nowhere.

### Security

- The README's WebSocket server sample is gone. It passed reader input through the host shell (`exec` with string interpolation, so `$(…)` ran on the host), crashed on one malformed frame, shared one container between readers and reported killed commands as success. If you deployed it, take it down. `examples/websocket-server/` replaces it: no host shell (node-pty with an argument array), one container per connection running as a non-root user without network, with a read-only root, no capabilities and CPU, memory and process limits, an origin allowlist (loopback by default), an optional token, connection and message rate limits, and logs without commands or output.
- AI suggestions are stripped of escape sequences and control characters, so an answer cannot hide part of the command or redraw the y/N question; commands over 2000 characters or taller than the screen are refused, and the command always sits directly above the question. Explanations and server error texts are cleaned the same way.
- AI suggestions containing invisible or format characters (`\p{Cf}`, `\p{Zl}`, `\p{Zp}`, unassigned code points, lone surrogates, Hangul fillers) are refused as invalid: bidirectional controls could otherwise show `echo hi # note; echo PWNED` at the y/N question while running `echo PWNED`. Emoji joined with zero-width joiners are refused too; explanations just lose those characters.
- A paste is handled as one unit from its first start marker to its last end marker, with markers inside stripped, so clipboard text containing a fake end-of-paste sequence can no longer break out of the paste and start an AI request.
- Run buttons never run text hidden from the reader (`hidden`, `aria-hidden`, `display: none`, `visibility: hidden`).
- Keys typed or pasted before the y/N question appears are discarded, so pasted text cannot answer it.
- Pasted lines that start with `#` no longer start AI requests that the reader pays for.
- Python runs in a Web Worker and can no longer read the page's DOM or `localStorage`, where readers' API keys live.
- An OpenAI-compatible key is sent only to the endpoint it was saved for, and a key the reader stored for api.anthropic.com is never sent to a custom `baseURL`.
- WebSocket connection errors show only the scheme, host, port and path of the server URL; tokens, credentials and fragments are never printed.
- The Python host validates the shape of every message from its worker.
- Documented limits (see "Security and limits" in the README): the JavaScript and Python workers run with the docs origin's authority (same-origin requests with cookies, IndexedDB, Cache Storage); `grep -E`/`-P` patterns with catastrophic backtracking can freeze the tab; Pyodide from the CDN loads without an integrity check, so self-host it in production.

## 0.7.0 - 2026-08-21

A real terminal instead of a line REPL: cursor editing, wrapped lines, Tab completion, streaming output, Ctrl+C with an `AbortSignal`, interactive programs (`InteractiveRun`) and a pager in the shell; the root entry became safe to import during server-side rendering.

## 0.6.0 - 2026-08-21

`docsterm/wasi`: programs compiled to `wasm32-wasi` run in the reader's browser.

## 0.5.0 - 2026-08-21

`docsterm/javascript` (a JavaScript REPL in a Web Worker) and `docsterm/websocket` (commands on your own server).

## 0.4.1 - 2026-08-21

Relative imports gained their `.js` extensions, so the package loads in plain Node. Versions 0.2.0 to 0.4.0 are deprecated on npm for this reason.

## 0.3.0 and 0.4.0 - 2026-08-21

`docsterm/openai` for OpenAI-compatible endpoints and `docsterm/shell`.

## 0.2.0 - 2026-08-21

One package with entry points replaced the five separate packages.
